# Встреча с заказчиком 29.10.2026 — баги, недоработки, новые изменения

Образец удобного сайта: https://newtondarts.com/tournament.html (NewTon DC Tournament Manager, открытый код) — можно брать идеи:
двойное выбывание, «группы + кубки A/B», швейцарка, розыгрыш мест, достижения, мишени (lanes), «Match Controls»,
подсветка пути игрока в сетке (остальное затемнено), сворачивание кругов сетки, судья (chalker), лимит подходов на лег.

## Список

1. **Время в турнире.** Вместо «осталось примерно» — «сколько прошло». Статистика времени: игроки у мишени — как только
   первый начал вносить, идёт его время; начал второй — время первого стоп, идёт время второго. Собрать статистику по
   времени (игрок, матч, весь турнир) и красиво показать.
2. **Большая сетка.** Сворачивать первые круги, чтобы следующим было больше места. Путь игрока: остальное затемнить
   (прозрачность), без мелькания, только свечение (как на скрине NewTon: путь — рамка/свечение, остальное бледное).
3. **Разные типы турниров/сеток.** Как в примере: Круговой (1 группа без сетки), Стандарт (групповой этап + сетка),
   Лига (1 группа + сетка), Сетка (без группового этапа), Комплексный (упражнения + группы + сетка); настройки:
   игроков в основной сетке, выходит из группы, автоматическое управление мишенями. Можно добавить свои
   (двойное выбывание, швейцарка, кубки A/B, розыгрыш всех мест).
4. **База данных.** Заказчик прислал схему Access (tblPlayers, tblCities, tblParticipation, tblResults, tblExercise,
   tblTournaments) — что должно быть на сайте. Показать, как устроена наша база. Не хватает: фамилия/имя отдельно,
   год рождения, пол, субъект РФ, заметки — нужны для протокола (п. 10).
5. **Режим «7 жизней»** (с листа: «кол-во дротиков? ограничение 45», «7 жизней», «победитель через булл»).
   Уточнить правила.
6. **Гибкие настройки для ведущих:** до скольких побед по стадиям сетки (финал до 5, полуфинал до 3, слабые сетки
   1–2, средние 2–3, сильные 3–7 и больше) — ведущий сам ставит; и другие настройки — настраиваемые.
7. **Судьи.** Назначать судей (главный судья турнира, судьи матчей), выбирать и настраивать; в сетке показывать,
   кто судил матч.
8. **Нет интернета у игрока** — локальная сессия: продолжают играть, при появлении сети результаты дойдут; если нет —
   показывают телефон, ведущий вносит сам.
9. **Аккаунты от ведущего** для тех, кто не умеет регистрироваться: ведущий заводит игрока (данные), у каждого свой
   QR на турнир и игру. В глобальную статистику не идут; профиль «лайт» — упрощённый, без статистики.
10. **Протокол результатов** в конце турнира — по образцу ГОСТ (файл LMG_Protokol_1_tura.pdf): шапка (название лиги и
    тура, «ПРОТОКОЛ РЕЗУЛЬТАТОВ», разряд «Одиночный»), место проведения и дата, судьи (главный судья, город),
    регламент («501», группы, олимпийская система с розыгрышем всех мест); таблица: место, фамилия имя, год рождения,
    звание/разряд, субъект РФ, город/клуб, выполненный разряд; подпись главного судьи. Плюс в конце — о нашем клубе.
    Идея: ведущий связывает своё сообщество VK — пост по кнопке (предпросмотр, правка, публикация) или предпросмотр
    и «скопировать», чтобы выложить самому.
11. **Вместо входа по коду от ведущего — QR.** Ведущий создал аккаунт (записал данные) → аккаунт сразу в его базе с
    номером + свой QR; игрок входит по QR и дальше пользуется этим же аккаунтом.
12. **Демо в браузере = сервер**, отличие только в заполненных данных и игроках; всё остальное точно такое же.
