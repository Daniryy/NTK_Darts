# Oche API

Договор между страницей и сервером. Сначала меняем здесь, потом в коде.

## Общее

- Адрес: `/api/...`, данные в JSON (`Content-Type: application/json`).
- Время — миллисекунды с 1970 года (как `Date.now()`).
- Идентификаторы — строки: игроки `p…`, турниры `t…`. Матч получает id от телефона (см. «Матчи»).
- **Устройство.** Каждый запрос (и на чтение тоже) содержит заголовок `X-Device-Id`, для записи он обязателен. Это случайная строка из 16–64 символов `[A-Za-z0-9_-]`, её один раз создают и хранят в `localStorage['oche.device']`. По ней работают замок матча и ограничение частоты.
- **Вход.** Сессия хранится в httpOnly-cookie `oche_sid`, её ставит сервер. Без входа доступно только чтение.
- **Ограничение частоты:** 10 запросов в секунду с устройства, кратковременно до 20. При превышении — `429` и заголовок `Retry-After`.
- **Ошибка** всегда приходит в таком виде:
  ```json
  { "error": { "code": "seq_gap", "message": "Ожидается подход №12", "expectSeq": 12 } }
  ```

| HTTP | code | Когда |
|---|---|---|
| 400 | `bad_request` | неверные поля; в `fields` указано, какие |
| 401 | `unauthorized` | нужен вход |
| 403 | `forbidden` | нет прав |
| 404 | `not_found` | нет такого объекта |
| 409 | `conflict`, `seq_gap`, `game_taken`, `result_locked`, `bad_state` | конфликт состояния, подробности в полях ошибки |
| 422 | `bad_event` | подход не сходится со счётом |
| 423 | `locked` | матч ведёт другое устройство |
| 429 | `too_many` | слишком часто |
| 500 | `server` | ошибка сервера |

## Вход и профиль

Войти можно четырьмя способами на выбор: по почте и паролю (игрок регистрируется сам), по номеру телефона (звонок-сброс или код из SMS), через VK ID или по коду от ведущего. К одному аккаунту можно привязать почту, телефон и VK.

**Роли** (`role`): `player` — игрок; `host` — ведущий (клуб подтверждён администратором); `admin` — администратор; `tech` — тех. администратор. Каждая следующая умеет всё, что предыдущая (см. «Права»). Заблокированный игрок (`blocked`) не может войти, его сессии закрываются.

### `GET /api/auth/vk?return=/путь[&link=1]`
Переход на страницу входа VK. После входа VK возвращает на `/api/auth/vk/callback`, сервер ставит cookie и перенаправляет на `return`. Страница делает обычную ссылку на этот адрес.
`link=1` (нужен вход) — привязать VK к своему аккаунту. Результат — в адресе возврата: `?login=linked`, `vk_taken` (этот VK у другого аккаунта), `blocked`, `fail`.

### `POST /api/auth/phone` — шаг 1 входа по телефону
`{ "phone": "+7 912 345-67-89" }` (8…, 9… без кода страны — российский номер). По умолчанию (`SMS_METHOD=call`) — звонок-сброс: код — последние 4 цифры номера, с которого звонят, отвечать не нужно; при `SMS_METHOD=sms` — SMS с кодом из 6 цифр. Код живёт 10 минут. Ответ `{ "ok": true, "wait": 60, "method": "call" | "sms", "digits": 4 | 6 }`; в разработке (`SMS_PROVIDER=log`) ещё `devCode` — ничего не отправляется.
- `429 too_many` (`retryAfter`, заголовок `Retry-After`) — код на этот номер уже отправлен меньше минуты назад; больше 5 кодов в час на номер или 10 с устройства;
- `503 sms_limit` — исчерпан суточный лимит SMS сервера (`SMS_DAY_MAX`);
- `502 sms_failed` — провайдер не смог позвонить или отправить SMS.

### `POST /api/auth/phone/verify` — шаг 2
`{ "phone", "code": "1234" }` → вход; номера ещё нет — создаётся игрок «Игрок 6789» (имя он поменяет в профиле). `{ …, "link": true }` (нужен вход) — привязать номер к своему аккаунту. Ответ — как у `GET /api/me` и `created: true | false`.
- `409 bad_code` — неверный код; после 3 неверных попыток (код звонка) или 5 (код SMS) код сгорает;
- `409 code_expired` — код устарел, использован или попытки кончились;
- `409 phone_taken` — номер привязан к другому аккаунту.

### `POST /api/auth/register` — регистрация по почте
`{ "name", "city"?, "email", "password" }` (имя 2–32 символа, пароль от 8 символов, не только цифры). Почта настроена (`SMTP_*`) — уходит письмо с кодом из 6 цифр, ответ `{ "ok": true, "sent": true, "wait": 60 }` (в разработке ещё `devCode`); аккаунт создаётся после `POST /api/auth/email/verify` с `purpose: "reg"`. Почта не настроена — аккаунт создаётся сразу с неподтверждённым адресом, ответ — как у `GET /api/me` и `created: true`.
- `409 email_taken` — почта уже зарегистрирована;
- `429 too_many` — письмо на этот адрес уже отправлено меньше минуты назад, больше 5 писем в час на адрес, 10 с устройства или 20 регистраций с IP в час;
- `503 mail_limit` — исчерпан суточный лимит писем (`MAIL_DAY_MAX`); `502 mail_failed` — письмо не ушло.

### `POST /api/auth/email/send` — письмо с кодом
`{ "email", "purpose": "link" | "reset" }`. `link` (нужен вход) — привязать почту к своему аккаунту; `409 email_taken` — почта у другого аккаунта. `reset` — код для нового пароля; ответ одинаковый для любых адресов (не выдаёт, есть ли аккаунт). `404` — почта на сервере не настроена. Лимиты — как у регистрации.

### `POST /api/auth/email/verify` — код из письма
`{ "email", "purpose": "reg" | "link" | "reset", "code": "123456", "password"? }`. `reg` — создать аккаунт и войти; `link` — почта подтверждена (код должен быть запрошен этим же аккаунтом); `reset` — `password` становится новым паролем, остальные сеансы закрываются, блокировка после неверных паролей снимается, вход. Ответ — как у `GET /api/me` и `created`. Код живёт 30 минут, 5 попыток.
- `409 bad_code` — неверный код; `409 code_expired` — устарел, использован или попытки кончились.

### `PUT /api/me/email` — почта без писем
Только когда письма на сервере не настроены (иначе `409 need_code` — через код): `{ "email", "password"? }` — почта привязывается сразу, неподтверждённой (`emailOk: false`); `password` (от 8 символов) нужен, если пароля ещё нет. Ответ — как у `GET /api/me`; `409 email_taken` — почта у другого аккаунта.

### `POST /api/auth/email/login` — вход по почте и паролю
`{ "email", "password" }` → сеанс (полгода; администраторам — 30 дней). `409 bad_login` — неверная почта или пароль (одинаково); `429 too_many` — 5 неверных паролей подряд (вход закрыт на 15 минут) или больше 10 попыток с IP за 10 минут.

### `POST /api/auth/code`
Вход по коду от ведущего: `{ "code": "K7MQ2XRA" }` (регистр, пробелы и дефисы не важны). Для тех, кто не может войти сам: ведущий заводит аккаунт и даёт код. Код одноразовый. Ответ — как у `GET /api/me`; `404` — кода нет.

### `POST /api/auth/password` — вход администратора
`{ "login": "danil", "password": "…" }` → сеанс на 30 дней. Только у ролей `admin` и `tech` (логин выдают `npm run admin` на сервере или тех. администратор в панели). Ответ — как у `GET /api/me`.
- `409 bad_login` — неверный логин или пароль (одинаково для обоих);
- `429 too_many` — 5 неверных паролей подряд: вход по этому логину закрыт на 15 минут; или больше 10 попыток с одного IP за 10 минут;
- `403` — роль ниже администратора или аккаунт заблокирован.

### `PUT /api/me/password`
Сменить свой пароль: `{ "current", "password" }`. Пароль администратора с логином — от 10 символов, игрока — от 8; не только цифры. Пароля ещё нет, но почта привязана — `current` не нужен (так игрок, вошедший по коду, телефону или VK, заводит вход по почте). `409 bad_login` — текущий неверный; `409` — нет ни пароля, ни почты.

**Лимиты входа по IP** (вдобавок к лимиту устройства, который можно обойти сменой id устройства): вход и привязка по коду — 60 за 10 минут, запрос кода по телефону — 30 в час, проверка кода — 60 за 10 минут.

### `DELETE /api/me/login/phone`, `DELETE /api/me/login/vk`, `DELETE /api/me/login/email`
Отвязать телефон, VK или почту. Последний способ входа отвязать нельзя — `409`. Ответ — как у `GET /api/me`.

### `GET /api/config`
Что умеет сервер: `{ "vk": true, "phone": true, "phoneBy": "call", "email": true, "dev": false }` — настроен ли вход через VK, по телефону (`phoneBy` — звонком или SMS), отправляются ли письма с кодами (`email`; регистрация по почте работает и без них), доступен ли вход для разработки.

### `POST /api/auth/logout`
Выход. Ответ `{ "ok": true }`.

### `POST /api/auth/dev` — только при `NODE_ENV=development`
Тело `{ "playerId": "p3" }`. Вход без VK для разработки.

### `GET /api/me`
```json
{ "player": { "id": "p17", "name": "Иван Петров", "handle": "ivan_p", "code": "OCH-4821", "city": "Москва", "club": "«Оче-бар»", "ver": false,
    "role": "host", "phone": "+79123456789", "vk": true, "email": "ivan@mail.ru", "emailOk": true, "pass": true, "login": null },
  "admin": false, "role": "host", "perms": ["club_tour", "streams", "accounts", "host_nums"], "clubs": [{ "id": "c1", "name": "Клуб «Тройная двадцатка»" }] }
```
`email` и `phone` видит только сам игрок (и администратор в карточке); `emailOk` — почта подтверждена кодом; `pass` — задан пароль. `code` — уникальный ID игрока: по нему ищут (`OCH-4821`, `#4821`, `4821`) и добавляют в турнир. `admin` — роль `admin` или `tech`. `clubs` — подтверждённые клубы, где игрок ведущий.
Если вход не выполнен, приходит `{ "player": null, "admin": false, "role": null, "clubs": [] }`, а не ошибка.

### `PATCH /api/me`
Тело `{ "name"?, "city"?, "club"?, "walkon"? }`. Ограничения: `name` 2–32 символа, `city` до 40; `club` — название открытого клуба из `GET /api/clubs` или пусто (`400`, если такого клуба нет; прежнее значение можно прислать без изменений). `walkon` — выходная музыка (до 60 символов), только с правом `pro`, иначе `403`. Звание так не меняется (`400`) — только заявкой. Ответ — как у `GET /api/me`.

### `POST /api/me/claim`
Привязать аккаунт, созданный администратором: `{ "code": "K7MQ2XRA" }` (регистр, пробелы и дефисы не важны). Сессия переходит к тому аккаунту, VK — тоже; свой пустой аккаунт удаляется.
- `404` — кода нет (код одноразовый);
- `409` — у своего аккаунта есть матчи, турниры, роль, звание, вход по паролю, клуб, номера ведущего, тариф или заявка: объединяет только администратор;
- `409 conflict` — у своего аккаунта уже есть матчи или турниры, или к тому аккаунту уже привязан VK, телефон или почта.

Почта и пароль своего аккаунта тоже переходят к тому аккаунту.

Ответ — как у `GET /api/me`.

## Фото

Страница сама обрезает и сжимает картинку (аватар — квадрат, итоги — 4:3) и присылает готовый файл.

### `POST /api/photos?kind=avatar[&playerId=p5]&w=400&h=400` — нужен вход
### `POST /api/photos?kind=tour&tournamentId=t4&w=1280&h=960` — организатор
С `&cover=1` фото становится общим фото игроков (`cover` турнира).
### `POST /api/photos?kind=banner&w=1200&h=300` — тех. администратор, картинка баннера
С `&clubId=c1` — картинка спонсора клуба (ведущий клуба с правом `club_tools`).

### `POST /api/photos?kind=club&clubId=c1&w=400&h=400` — логотип клуба
Ведущий клуба с правом `club_tools`; прежний логотип удаляется. Ответ `201 { photo }`, адрес — в `clubs.logo`.
Тело — сама картинка, `Content-Type: image/jpeg | image/webp | image/png`, до 3 МБ. `w`, `h` — размер в точках (16–4096).
- Аватар: свой; гостя, которого создал я; любой — администратору. Новый заменяет старый.
- Итоги турнира: до 60 фото, меняет версию турнира.

Ответ `201 { "photo": { "id": "…", "url": "/uploads/….jpg", "w": 400, "h": 400 }, "player": PlayerShort }` (`player` — у аватара).

### `DELETE /api/players/:id/photo`
Убрать аватар игрока (права — как на загрузку). Ответ `{ "ok": true }`.

### `DELETE /api/photos/:id`
Свой аватар, аватар своего гостя, фото турнира — организатор; администратор — любое. Ответ `{ "ok": true }`.

## Администратор

Аккаунты заводят ведущие и администраторы. Ведущий видит и правит только аккаунты, которые завёл сам.

### `GET /api/admin/players?q=&limit=50&role=&mine=1&blocked=1` — ведущий, администратор
Игроки с полями `vk` (привязан ли VK), `phone`, `claim` (код входа или `null`), `role`, `blocked`, `owner` (кто завёл), `created`. Поиск — по имени, `@handle`, ID и цифрам телефона. Ответ `{ "players": [...] }`.

### `POST /api/admin/players` — ведущий, администратор
`{ "name", "city"?, "club"?, "title"?, "phone"?, "n"? }` — новый аккаунт с кодом входа. Код отдают игроку: он входит по нему («Код от ведущего»), а уже вошедший через VK или телефон — привязывает в профиле (`POST /api/me/claim`). `n` — номер в списке ведущего (`/api/host/nums`). Ответ `201 { "player": … }`; `409 phone_taken` — номер занят.

### `PATCH /api/admin/players/:id`
`{ "name"?, "city"?, "club"?, "title"?, "claim": true | false }` — ведущий (свои аккаунты) и администратор; `claim: true` — новый код входа, `false` — убрать. Аккаунту с телефоном или логином новый код выдаёт только администратор (ведущему — `403`).
`{ "ver"?, "blocked"?, "role"? }` — администратор: `role` `player` или `host`; `admin` и `tech` выдаёт и меняет только тех. администратор. Свою роль менять и себя блокировать нельзя (`409`). Ответ `{ "player": … }`.

### `GET /api/admin/stats` — право `stats`
Сводка: `players`, `roles` (`{ player, host, admin, tech }`), `newWeek`, `blocked`, `tours` (`{ reg, live, done }`), `liveMatches`, `matchesDay`, `clubsPending`, `smsDay`.

### `GET /api/admin/players/:id` — карточка игрока (право `players`, или `accounts` для своих аккаунтов)
`{ player, owner, clubs, sessions, matches, tours, owned, locked, log }`: аккаунт, кто завёл, клубы ведущего, действующих сеансов, матчей, турниров, заведённых им аккаунтов, до какого времени закрыт вход по паролю, последние 20 записей журнала об игроке (с правом `audit`).

### `POST /api/admin/players/:id/logout` — право `players`
Завершить все сеансы игрока. Ответ `{ ok, sessions }`.

### `DELETE /api/admin/players/:id` — право `delete_players`
Удалить аккаунт без возврата: профиль, вход, сеансы, тарифы, заявки. Себя — нельзя (`409`); администраторов — только тех. администратор (`403`). Игрок в идущем или сыгранном турнире не удаляется — `409 in_tournaments` (его можно заблокировать); из турниров на регистрации запись убирается. Дружеские матчи остаются у соперников без ссылки на игрока. Ответ `{ ok: true }`; в журнале `player.delete` с именем и ID.

### `POST /api/admin/cleanup` — право `cleanup`
Очистка сервера от демо-данных, тело `{ "confirm": true }`. На сервере (`NODE_ENV=production`) сначала `deploy/backup.sh` — не вышло, очистка отменяется (`500 backup_failed`). Удаляются все турниры и матчи, клубы, баннеры и игроки без входа; остаются аккаунты с логином, почтой, телефоном или VK, заведённые ими и тот, кто чистит; рейтинг и статистика обнуляются. Ответ `{ tours, matches, players, kept, removed, files }`.

### `PUT /api/admin/players/:id/login`, `DELETE /api/admin/players/:id/login` — тех. администратор
Выдать (`{ login, password }`) или убрать вход по логину и паролю. Только для ролей `admin` и `tech`; `409 login_taken` — логин занят. При понижении роли ниже администратора логин снимается сам.

### Права ролей
`GET /api/admin/perms` → `{ perms: [{ key, name, min, roles }], roles: ["player", "host", "admin"] }`.
`PUT /api/admin/perms` (тех. администратор) — `{ perms: { ключ: [роли] } }`, только изменённые. Тех. администратору доступно всё; выдача ролей `admin`/`tech` и сами права не настраиваются.

| Право | По умолчанию | Что разрешает |
|---|---|---|
| `create_tour` | все роли | создавать свои турниры |
| `club_tour` | ведущий | турниры от имени своего клуба |
| `club_tools` | ведущий | логотип и спонсоры клуба на табло, помощники, взносы, статистика клуба |
| `streams` | ведущий | камеры в своих турнирах |
| `accounts` | ведущий | заводить аккаунты с кодом входа (видеть свои) |
| `host_nums` | ведущий | свои номера игроков |
| `players` | администратор | править любых игроков, подтверждать, коды, завершать сеансы |
| `contacts` | администратор | видеть телефон и почту игроков в списке и карточке (свои аккаунты видны всегда); без права — «скрыт», поиск по ним не работает |
| `block` | администратор | блокировать |
| `give_host` | администратор | выдавать и снимать роли игроков: ведущий и свои роли (ранг 1) |
| `clubs` | администратор | клубы и их ведущие |
| `any_tour` | администратор | любые турниры и матчи |
| `official` | администратор | официальный статус турниров |
| `pro` | ведущий, Pro | статистика Pro, личные встречи, выгрузка, выходная музыка, без рекламы |
| `plans` | администратор | тарифы: подключать по заявке и вручную, продлевать, завершать |
| `stats` | администратор | сводка |
| `titles` | администратор | проверять, подтверждать и снимать звания |
| `audit` | администратор | журнал |
| `banners` | тех. администратор | баннеры |
| `plans_edit` | тех. администратор | тарифы: цены и состав (`POST`, `PATCH /api/admin/plans`), скидки за звание |
| `delete_players` | тех. администратор | удалять аккаунты |
| `cleanup` | тех. администратор | очистка сервера от демо-данных |

### `GET /api/admin/audit?limit=50&before=время&target=id` — право `audit`
Журнал: `{ items: [{ id, t, actor: { id, name } | null, action, target: { id, name } | null, data }] }`, новые сверху. `actor: null` — команда с сервера. Действия: `login.password`, `login.email`, `email.link`, `email.set`, `password.change`, `password.reset`, `player.create`, `player.edit`, `player.role`, `player.block`, `player.delete`, `cleanup`, `player.logout`, `player.login`, `player.login_off`, `perms`, `club.active|rejected|closed|edit`, `club.host_add`, `club.host_rm`, `banner.create|edit|delete`, `club.helper_add|helper_rm`, `title.*`, `plan.request|grant|extend|reject|end|create|edit`, `discounts`, `role.create|rename|delete`, `cli.*`.

## Звания

Спортивное звание или разряд в профиле — только после проверки документа; самому вписать нельзя (`PATCH /api/me` с другим `title` — `400`). Стадии для игрока: **1 подача → 2 автопроверка → 3 ручная проверка → 4 подтверждено ✅** (или отклонено с причиной). Подтверждённое звание — поле `title` игрока (`МС`, `КМС`, `1 разряд`…) во всех карточках.

Звания (`k`): `zms` ЗМС, `msmk` МСМК, `ms` МС (присваивает Минспорт России), `kms` КМС, `r1` 1 разряд (орган власти субъекта РФ), `r2`, `r3`, `y1`–`y3` — разряды и юношеские разряды.

### `GET /api/titles/kinds`
`{ kinds: [{ k, short, full, issuer, fed }] }`.

### `POST /api/titles/docs` — нужен вход
Файл документа телом запроса: JPEG, PNG, WebP или PDF до 8 МБ (тип определяется по содержимому). Ответ `201 { doc: { id, mime, url } }`. Файлы лежат в закрытой папке (`PRIVATE_DIR`), не через `/uploads/`.

### `GET /api/titles/docs/:id`
Файл — только владельцу и тем, у кого право `titles`; остальным `404`. `Cache-Control: private, no-store`.

### `POST /api/titles` — заявка
`{ fullName, title, orderNo, orderDate, issuer, comment?, docs: [id] }` (ФИО как в документе, 1–5 файлов). Сразу проходит автоматическая проверка, заявка получает `status: "review"`. Ответ `201 { request: TitleRequest }`; `409` — заявка уже на проверке.

**TitleRequest:** `{ id, title, short, full, fullName, orderNo, orderDate, issuer, comment, status: review | approved | rejected | cancelled, auto: [{ k, st: ok | warn | info, label, text }], autoAt, note, created, decided, docs: [{ id, mime, url }] }`.

Автопроверка (`auto`): документ приложен; ФИО совпадает с именем в профиле; номер и дата приказа указаны и правдоподобны; кто присвоил (МС, МСМК, ЗМС — только Минспорт России); тот же приказ с тем же ФИО уже подтверждён у другого аккаунта; уже есть звание выше; для федеральных званий — ссылка на поиск приказа на сайте Минспорта (только администратору). `label` — короткая подпись пункта («Документ», «ФИО», «Приказ», «Присвоил», «Повторы», «Сейчас», «Минспорт»), `text` — коротко итог («1 файл», «совпадает с профилем», «№ 45 нг от 10.03.2025»); у `minsport` в `text` ссылка поиска. `warn` — на что администратору обратить внимание; решение всегда за ним.

### `GET /api/titles/mine`, `DELETE /api/titles/:id`
Мои заявки (новые сверху) и подтверждённое звание `title`; отозвать заявку, пока она на проверке.

### `GET /api/admin/titles?status=review|approved|rejected|cancelled|all` — право `titles`
Заявки с игроком (`player: { id, name, code, title }`), ссылкой `search` и `decidedBy`.

### `PATCH /api/admin/titles/:id` — право `titles`
`{ status: "approved" | "rejected", note }` — при отказе `note` обязателен (игрок его видит). Подтверждение ставит игроку `title`.

### `DELETE /api/admin/players/:id/title` — право `titles`
Снять подтверждённое звание: `{ note }` пишется в журнал. Администратор с правом `titles` может и сразу задать звание в карточке игрока (`PATCH /api/admin/players/:id` с `title`).

## Роли и тарифы

Роли хранятся в базе (`roles`): `player` (ранг 0), `host` и свои роли (ранг 1), `admin` (2), `tech` (3). Свои роли добавляет тех. администратор — например, для тарифа; что им доступно, настраивается в «Правах ролей» как у остальных (по умолчанию — ничего сверх игрока).

Тариф даёт роль на срок. Онлайн-оплаты пока нет: игрок оставляет заявку, администратор подключает. Роль игрока складывается из роли, выданной вручную (`base_role`, её ставит `PATCH /api/admin/players/:id` с `role`), и действующего тарифа (при двух — того, что кончается позже): тариф повышает роль, а роль того же ранга не заменяет — ведущий с «Игрок+» остаётся ведущим. Кончился тариф — игрок возвращается к роли, выданной вручную. Администраторов тарифы не трогают. По окончании срока роль снимается сама (сервер проверяет раз в 10 минут и при старте).

Скидка за подтверждённое звание (`settings.discounts`, меняет тех. администратор): `ms` — МС, МСМК, ЗМС (по умолчанию 25%), `kms` — КМС (10%), `r1` — 1 разряд (5%). Цена округляется до рубля.

**Plan:** `{ id, name, price, days, role, about, active, sort, discount, why, final }` — `final` цена со скидкой текущего игрока, `why` — за что скидка.
**Sub:** `{ id, player?, plan: { id, name, price, days }, status: requested | active | ended | rejected | cancelled, price, discount, starts, ends, note, created, by }`.

### `GET /api/roles`
`{ roles: [{ key, name, rank, builtin }] }` — для значков и списков ролей.

### `GET /api/plans`
`{ plans: [Plan], mine: [Sub], request: Sub | null, discounts }` — тарифы с моей скидкой, мои действующие, моя заявка.

### `POST /api/plans/:id/request` — нужен вход
`{ note? }`. Ответ `201 { request: Sub }`; `409` — заявка уже есть.

### `DELETE /api/plans/requests/:id`
Отозвать свою заявку.

### `GET /api/admin/plans` — право `plans`
`{ plans, requests: [Sub + final], active: [Sub], discounts, discountKeys: [{ k, name }] }`.

### `POST /api/admin/plans/grant` — право `plans`
`{ requestId }` или `{ playerId, planId, days?, note? }`. Тот же тариф уже действует — срок прибавляется к его концу (`plan.extend`), иначе новое подключение с сейчас (`plan.grant`). Ответ `{ sub }`.

### `POST /api/admin/plans/requests/:id/reject` — право `plans`
`{ note }`.

### `POST /api/admin/plans/subs/:id/end` — право `plans`
Завершить сейчас; роль пересчитывается.

### `GET /api/admin/players/:id/plans` — право `plans`
Последние 20 подключений и заявок игрока.

### `POST /api/admin/plans`, `PATCH /api/admin/plans/:id` — тех. администратор
`{ name, price, days, role, about, active?, sort? }`; роль тарифа — не выше ранга 1.

### `PUT /api/admin/discounts` — тех. администратор
`{ ms, kms, r1 }`, 0–90.

### `POST /api/admin/roles`, `PATCH /api/admin/roles/:key`, `DELETE /api/admin/roles/:key` — тех. администратор
`{ name }`. Новая роль получает ключ `roleN` и ранг 1. Встроенные роли не удаляются; роль с игроками или тарифом — `409`.

## Тариф Pro

Право `pro`: по умолчанию у роли тарифа Pro (`plus`), ведущего и администратора. Без права — `403`.

### `GET /api/me/pro?period=30|90|365|all`
Статистика за период (по умолчанию 90 дней), матчи x01 без попыток квалификации, до 500 последних:
```json
{ "period": "90", "since": 1784900000000,
  "summary": { "n": 21, "w": 6, "avg": 59.3, "f9": 64.9, "co": 21.6, "c180": 8, "c140": 3, "c100": 20, "hco": 158 },
  "prev": { … за такой же период до этого, у all — null },
  "form": [{ "t": 1787000000000, "n": 4, "avg": 58.1, "co": 25 }],
  "visits": 412,
  "co": [{ "lo": 2, "hi": 40, "att": 10, "hit": 5, "pct": 50 }],
  "top": [{ "s": 32, "att": 7, "hit": 3, "pct": 42.9 }],
  "bands": [{ "label": "100–139", "n": 18, "pct": 18 }],
  "records": [{ "label": "Набор очков · 10 подходов", "unit": "очков", "best": 697, "at": 1787000000000, "legs": 5 }],
  "peers": { "n": 9, "lo": 1292, "hi": 1492, "avg": 67, "co": 89 } }
```
- `form` — среднее по неделям (до 90 дней) или по месяцам, не больше 26 точек.
- `co` — закрытия по остаткам из подходов счётчика: попытка — подход с остатком, который можно закрыть одним подходом (с дублем — по `Games.FIN`), попадание — закрыл. `top` — 12 самых частых остатков. Отменённые подходы не считаются.
- `bands` — наборы за 3 дротика с остатком больше 170, доли в %.
- `records` — лучший лег каждого упражнения (не x01) за всё время.
- `peers` — игроки с рейтингом ±100 и от 300 дротиков: процент тех, у кого среднее (`avg`) и закрытия (`co`) хуже ваших; `null`, если нет рейтинга.

### `GET /api/players/:id/h2h`
Личные встречи со мной: `{ n, w, l, legs: [мои, его], avg: [моё, его], matches: [MatchCard] }` — последние 10 матчей. Себя — `400`.

### `GET /api/me/export.csv`
Все мои матчи в CSV для Excel (UTF-8 с BOM, разделитель `;`): дата, турнир, игра, соперник, счёт, итог, среднее, первые 9, 180, закрытия, макс. закрытие.

## Клубы

Игрок подаёт заявку, администратор подтверждает — подавший становится ведущим клуба. Сам клуб роль не даёт: турниры от имени клуба, камеры, свои номера, аккаунты для игроков и инструменты клуба (`club_tour`, `club_tools` и др.) — у роли `host`, её даёт тариф «Ведущий» (или администратор вручную). Без тарифа у клуба есть страница с расписанием, а ведущему клуба страница показывает, что даёт тариф.

**Клуб**: `{ "id": "c1", "name", "city", "address", "contact", "about", "status": "pending" | "active" | "rejected" | "closed", "hosts": [{ "id", "name", "photo" }] }`; в ответах заявителю и администратору ещё `owner` (`{ id, name }`), `note` (ответ администратора), `created`, `decided`.

### `GET /api/clubs`
Открытые клубы. Ответ `{ "clubs": [Club] }`.

### `GET /api/clubs/mine` — нужен вход
Свои заявки и клубы, где я ведущий.

### `POST /api/clubs` — нужен вход
Заявка: `{ "name", "city"?, "address"?, "contact"?, "about"? }`. Ответ `201 { "club": … }`. `409` — заявка уже на рассмотрении или название занято.

### `GET /api/admin/clubs?status=pending` — администратор
### `PATCH /api/admin/clubs/:id` — администратор
`{ "status"?: "active" | "rejected" | "closed", "note"?, "name"?, "city"?, "address"?, "contact"?, "about"? }`. `active` — подтвердить: заявитель становится ведущим клуба (роль не меняется — её даёт тариф).

### `POST /api/admin/clubs/:id/hosts`, `DELETE /api/admin/clubs/:id/hosts/:playerId` — администратор
Добавить (`{ "playerId" }`) или убрать ведущего подтверждённого клуба.

### `GET /api/clubs/:id` — страница клуба, всем
`{ club: Club + logo, upcoming: [TourCard], past: [TourCard], players: [PlayerShort + visits], photos: [{ id, url, w, h, tid }], manage, tools }` — расписание (регистрация и идущие), 10 прошедших, 10 сильнейших игроков клуба за полгода, 12 последних фото. `manage` — я ведущий клуба (или администратор с правом `clubs`); `tools` — ещё и право `club_tools` (тариф «Ведущий»), тогда в ответе:
- `helpers: [PlayerShort]` — помощники;
- `banners: [{ id, place, title, body, image, link, active, clicks }]` — спонсоры клуба;
- `stats: { months: [{ t, players, visits }], regulars: [{ id, name, n }], lapsed: [{ id, name, last }], newMonth, cash30 }` — игроки на турнирах клуба по 6 месяцам, постоянные (3+ турнира за 60 дней), пропавшие (2+ турнира 60–180 дней назад и ни одного за 60 дней), новые за 30 дней, касса за 30 дней по отметкам «оплатил».

### `PATCH /api/clubs/:id` — ведущий клуба
`{ city?, address?, contact?, about? }`; название меняет администратор (`403`).

### `POST /api/clubs/:id/helpers`, `DELETE /api/clubs/:id/helpers/:playerId` — ведущий клуба, право `club_tools`
Помощники (до 5): в турнирах клуба ведут счёт любой пары, ставят мишени, вносят результаты квалификации и отмечают взносы (`can.staff`). Менять, запускать и удалять турнир, ссылки и камеры — нельзя. Ведущие клуба — соорганизаторы всех турниров клуба (`can.org`).

### `POST /api/clubs/:id/banners`, `PATCH /api/clubs/:id/banners/:bid`, `DELETE …` — ведущий клуба, право `club_tools`
Спонсоры клуба: поля как у баннеров, `place` — `tour` или `tv`, не больше 10. На турнирах клуба, где хотя бы у одного ведущего есть право `club_tools`, `GET /api/banners?place=…&tid=…` отдаёт только их (`club: true`), без баннеров Oche; там же `org.logo` — логотип клуба.

### `GET /api/rating?sort=r|avg&region=Свердловская%20область&q=текст&limit=100&offset=0`

```json
{ "total": 312, "cities": ["Екатеринбург", "Москва"], "regions": [{ "name": "Свердловская область", "n": 40 }],
```

### `GET /api/feed?scope=all|my&before=время&limit=30`

```json
  { "type": "tournament", "t": 1760000000000, "tournament": TourCard }

```
- `type: "tournament"` — турнир завершён, у `TourCard` есть `champion`.
- `my` — только с моим участием (нужен вход).
- Следующая страница — `before` = `t` последнего элемента.

**`MatchCard`** — то же, что объект матча на странице:
```json
{ "id": "g8x2k1q9zp", "t": 1760000000000, "tid": "t4", "tname": "Кубок Лиги · этап 4", "r": 2, "i": 0, "label": "круг 3 · за 1–4 места", "off": true,
  "mode": 501, "ltw": 3, "dbl": true, "w": 0, "quick": false,
  "pl": [ Line, Line ] }
```
- `tid`, `tname`, `r`, `i`, `label` равны `null` у дружеских матчей. `label` — подпись игры, как `gameLabel()` на странице.
- `quick: true` — счёт внесён без бросков: у строк `pts` и `darts` равны 0, `f9` равно `null`.
- `Line`: `{ "id": "p1"|null, "n": "имя", "legs": 3, "pts": 1203, "darts": 48, "f9": 92.1, "hi": 140, "hco": 81, "c180": 1, "c140": 3, "c100": 8, "coh": 3, "coa": 7, "bl": 15 }`. У гостя `id: null`.
- Протокол с подходами — `GET /api/matches/:id`.
- `ex` — упражнение (см. «Упражнения»), `null` у обычного x01. `q` — `{ "id": "p5", "k": 0 }` у попытки квалификации (`label`: «квалификация · попытка 1»), иначе `null`. Попытки квалификации в ленту не попадают.
- У строк упражнений `sc` — итоги легов (`[845, 790]`), у x01 `null`. `pts` и `darts` — очки (у «Сектора» — попадания, у крикета — метки) и дротики за матч: средний за подход = `pts / darts × 3`. В статистику игрока (средние x01) упражнения не входят.

## Упражнения

Матч состоит из легов, лег — одно упражнение. Правила и счёт — в общем модуле `shared/games.js` (страница и сервер считают одинаково).

**`Ex`:**
```json
{ "k": "x01", "mode": 501, "dbl": true, "lim": 10 }
{ "k": "score", "lim": 10 }
{ "k": "round" }
{ "k": "sector", "sec": 20, "lim": 10 }
{ "k": "cricket", "lim": 10 }
```
- `x01` — до нуля; `lim` — подходов на игрока в леге (0 — без ограничения). Обычный x01 без лимита в API — `ex: null` и поля `mode`, `dbl`.
- `score` — «Набор очков»: сумма за `lim` подходов.
- `round` — «Большой раунд»: 21 подход — сектора 1…20 и булл; очки = попадания в нужный сектор × номер сектора (дубль — 2 попадания, трипл — 3; 25 — 1, булл — 2, по 25).
- `sector` — «Сектор `sec`»: число попаданий за `lim` подходов (дубль — 2, трипл — 3).
- `cricket` — 15–20 и булл; лег выигрывает тот, кто закрыл всё и не отстаёт по очкам; `lim` — подходов на игрока (0 — до закрытия).
- **Лег без закрытия** (кончился лимит подходов): выигрывает меньший остаток (x01), больше очков (крикет: затем больше меток) или больше результат. При равенстве — бросок в булл: событие `bull`.
- Лег `k` начинает игрок `(starter + k − 1) mod число игроков`, бросают по очереди.

## Турниры

**`Tour`** — турнир в том же виде, в котором страница хранит его сейчас. Плюс поля `version`, `live`, `roster`, `can`:
```json
{
  "id": "t4", "name": "Кубок Лиги · этап 4", "official": true,
  "org": { "id": "p1", "name": "Лига Oche", "ver": true },
  "city": "Москва", "venue": "Клуб «Тройная двадцатка»",
  "start": 1760000000000, "regUntil": null, "status": "live",
  "format": "pl", "mode": 501, "ltw": 3, "dbl": true, "cap": 16,
  "players": ["p1", "p2"],
  "slots": ["p1", null, "p8"],
  "games": [{ "r": 0, "i": 0, "res": { "la": 3, "lb": 1, "w": "p1", "mid": "g8x2k1q9zp" } }, { "r": 0, "i": 1, "res": null }],
  "live": { "0:1": "gq7p0c2mzt" },
  "roster": { "p1": { "name": "Артём Волков", "city": "Москва", "club": "…", "r": 1704 } },
  "version": 57,
  "can": { "org": false, "stream": false, "edit": false, "delete": false, "launch": false, "score": true, "staff": false, "fees": false, "join": false },
  "fees": { "fee": 500, "paid": ["p1"] }
}
```
- **`status`:**
  - `reg` — идёт регистрация;
  - `live` — идёт;
  - `done` — все матчи сыграны (сервер считает так же, как `tStatus()`).
- **`slots`** — только у `pl` и `ko`. Это посев: `null` значит свободное место.
- **`games`:**
  - в `pl` и `ko` это все игры сетки (`r`, `i`, `res`), кругом за кругом;
  - в `rr` у каждой игры также есть `a` и `b`;
  - при регистрации `games: []`;
  - сетку, номера, места и подписи страница считает сама через `shared/bracket.js`.
- **`live`** — какие игры сейчас идут: `"r:i"` → id матча; попытки квалификации — `"q:p5:0"` → id матча.
- **`ex`** — упражнение матчей (`Ex`), нет поля — обычный x01 по `mode` и `dbl`.
- **Квалификация** (формат NDL):
  - `qual` — `{ "ex": Ex, "tries": 2, "res": { "p5": [{ "v": 845, "mid": "g…", "t": 1760000000000 }, null] } }`: упражнение, сколько попыток, результаты (`mid` — матч счётчика или `null`, если внёс организатор);
  - `stage: "qual"` — квалификация идёт, сетки ещё нет (`games: []`, `slots` нет);
  - после закрытия места 1–`split` играют первую часть сетки, следующие — вторую и т. д.
- **`split`** — размер части сетки (8 у NDL). **`block`** — части построенной сетки: `slots` идут частями по `block`, номер игры `i` сквозной (см. `shared/bracket.js`). Нет `block` — сетка одна.
- **`res.avg`** — средний набор игроков за подход в сыгранной игре: `[a, b]`, `null` без бросков.
- **`boards`** — мишени: `{ "n": 6, "at": { "1:3": 2 }, "names": [3, 5, 7, 8, 11, 12], "q": { "p5": 1 } }`:
  - `n` — сколько их; внутри мишени — порядковые 1…n, `names` — их номера в зале (нет поля — номера 1…n);
  - `at` — у какой готовой игры какая. Сыгранная игра освобождает мишень, свободные получают готовые игры по порядку номеров;
  - `q` — на квалификации: какой игрок у какой мишени. По двое на мишень (бросают по очереди), сначала по одному на каждую; сдавший все попытки освобождает место следующему по номеру.
- **`ready`** — «Готов» у мишени: `{ "1:3": { "p5": время } }` — кто из пары готовой игры уже отметился.
- **`pace`** — темп турнира: `{ "match": мс, "qual": мс }` — средняя длительность матча и попытки квалификации в счётчике (без быстрого счёта); `null` — ещё не было. Страница по нему пишет «осталось ≈ 40 мин».
- **`photos`** — фото к итогам `[{ "id", "url", "w", "h" }]`, **`links`** — ссылки `[{ "title", "url" }]`.
- **`nums`** — номера игроков в турнире `{ "p5": 7 }`; нет поля — номер = позиция в `players` + 1. После квалификации номер = место в квалификации.
- **`roster`** — данные всех участников, чтобы не запрашивать их отдельно; ещё `walkon` (выходная музыка — табло показывает её до первого броска) и `pro: true` — значок PRO (право `pro`, кроме администраторов).
- **`can`** — что разрешено текущему пользователю:
  - `org` — текущий пользователь организатор (или админ): квалификация, мишени, номера;
  - `edit`, `delete`, `launch` — организатору;
  - `score` — вести счёт в этом турнире;
  - `join` — можно записаться или отписаться.

**`TourCard`** — для списков:
```json
{ "id": "t4", "name": "…", "official": true, "org": { "id": "p1", "name": "…", "ver": true }, "city": "Москва", "venue": "…",
  "start": 1760000000000, "regUntil": null, "status": "live", "format": "pl", "mode": 501, "ltw": 3, "cap": 16,
  "count": 16, "progress": { "done": 18, "total": 32 }, "champion": null, "joined": true, "version": 57,
  "ex": null, "qual": null, "split": null, "stage": null, "fee": 500, "cover": null, "podium": null }
```
Во время квалификации `progress` — сколько игроков сдали из всех. `fee` — взнос или `null`; у сыгранного турнира `cover` (общее фото) и `podium: [{ id, name, lo, hi }]` — призёры (места 1–3, до 4 человек) для карточки итогов в ленте.

### `GET /api/tournaments?status=reg|live|done&city=&q=&mine=1&limit=30&offset=0`
Ответ `{ "total": 12, "tournaments": [TourCard] }`. `mine=1` — я участник или организатор (нужен вход).

### `GET /api/tournaments/:id?since=57`
- Изменений после версии 57 нет — `204` без тела.
- Есть — `{ "tournament": Tour }`, целиком: он маленький (до 15 КБ), почти все опросы получают `204`.

Версия растёт, когда:
- меняется запись участников или настройки;
- турнир запускается;
- матч начинается, заканчивается или отменяется.

Отдельные подходы версию турнира **не** меняют.

### `POST /api/tournaments` — нужен вход
```json
{ "name": "Мой турнир", "city": "Москва", "venue": "«Оче-бар»", "format": "pl", "mode": 501, "ltw": 2, "seed": "r",
  "players": ["p1", "p5", "p9"], "reg": false, "regUntil": null, "cap": null, "start": null }
```
- `reg: false` — сразу запуск: сервер делает посев (`seed: r` по рейтингу, `x` жеребьёвкой) и строит сетку.
- `reg: true` — открыть регистрацию; `players` можно не передавать, `cap` (лимит мест) обязателен.
- `ex` — упражнение матчей (`Ex`); тогда `mode` можно не передавать. `ex: { k: "x01", … }` без лимита сохраняется как обычный `mode`/`dbl`.
- **NDL:** `format: "pl"`, `qual: { "ex": { "k": "score" }, "tries": 2 }` и `split: 8` (по умолчанию 8). Запуск открывает квалификацию (`stage: "qual"`), порядок `players` — как прислали (это номера до квалификации). Упражнение квалификации — `score`, `round` или `sector`.
- `split` без `qual` — сетка частями по посеву (места 1–8, 9–16…).
- **Вид сетки** (`pl`, `ko`): `layout: "ndl"` — порядок матчей как на бумажном листе NDL (1–8, 5–4, 3–6, 7–2), `"std"` — классический (1–8, 4–5, 2–7, 3–6); по умолчанию `ndl`. Пары и дальнейшие встречи одинаковые, отличается только порядок сверху вниз. `labels: "ab"` — подписи как на листе: в первом круге номера посева («1–8»), дальше места A1–A2, B1–B2 («победитель → A1, проигравший → A5»); `"num"` — номера №1, №2… По умолчанию `ab` у турниров с квалификацией, иначе `num`. В `Tour` — поля `layout` и `labels` (у старых турниров нет: классический порядок и номера). Подписи считает `Bracket.gameTag`, `slotTag`, `nextOf`.
- `clubId` — турнир от имени клуба (ведущий этого клуба или администратор): официальный, подпись организатора — название клуба, в `org.club` — id клуба. В `PATCH` — так же, `clubId: null` убирает.

Только администратор может передать `official`, `orgName`, `orgVer` (официальный турнир от имени клуба или лиги).

Ограничения:

| Поле | Допустимые значения |
|---|---|
| `name` | 1–60 символов |
| `venue` | до 60 символов |
| `city` | до 40 символов |
| `format` | `pl`, `ko`, `rr`; `qual` и `split` — только `pl` |
| `mode` | 301, 501, 701 |
| `split` | 4, 8, 16, 32 |
| `layout` | `ndl`, `std` |
| `labels` | `ab`, `num` |
| `qual.tries` | 1–2 |
| `ltw` | 1–5 |
| участники | `pl`/`ko` — 3–64, `rr` — 3–10, без повторов |

Ответ `201 { "tournament": Tour }`.

### `PATCH /api/tournaments/:id` — организатор, только при `status: reg`
Любые поля из создания, кроме `players`. Ответ `{ "tournament": Tour }`.
Исключение: `{ "labels": "ab" | "num" }` (только это поле) можно менять и после старта — это лишь вид подписей.

### `DELETE /api/tournaments/:id` — организатор
Удаляет турнир и его матчи. Ответ `{ "ok": true }`.

### `POST /api/tournaments/:id/entries` — при `status: reg`
Тело `{ "playerId": "p5" }`:
- без тела — записать себя;
- с `playerId` — организатор записывает любого.

Ошибки:
- `409 conflict` с `"reason": "full"` — нет мест;
- `409 conflict` с `"reason": "already"` — игрок уже записан.

Ответ `{ "tournament": Tour }`.

### `DELETE /api/tournaments/:id/entries/:playerId` — себя или организатор, при `status: reg`
Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/launch` — организатор
Закрыть регистрацию и построить сетку (посев по рейтингу). Если участников меньше 3 или больше лимита формата — `409 bad_state`. Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/games/:r/:i/result` — `can.score`
Быстрый счёт без бросков: `{ "la": 3, "lb": 1 }`. Победитель должен выиграть ровно `ltw` легов.

Ошибки:
- `409 game_taken` с `matchId` — игра идёт или уже сыграна;
- `409 bad_state` — игра ещё не готова (соперник не определён).

Ответ `{ "tournament": Tour, "match": MatchCard }`.

### `PUT /api/tournaments/:id/qual/:playerId/:try` — организатор, при `stage: qual`
Результат попытки вручную: `{ "v": 845 }`. `try` — с 0; попытка `k` — только после попытки `k − 1`. `v` — от 0 до максимума упражнения (`score` — 180 × `lim`, `round` — 2040, `sector` — 9 × `lim`).

Ошибки:
- `409 game_taken` — попытка идёт или сыграна в счётчике;
- `409 bad_state` — нет предыдущей попытки или квалификация закрыта.

Ответ `{ "tournament": Tour }`.

### `DELETE /api/tournaments/:id/qual/:playerId/:try` — организатор, при `stage: qual`
Удалить результат этой и следующих попыток (вместе с их матчами). Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/qual/close` — организатор
Закончить квалификацию: порядок по лучшему результату, затем по второй попытке, затем по рейтингу (кто не сдал — в конце). Сетка строится частями по `split` мест, `nums` — места квалификации.
- `409 bad_state` — квалификация уже закрыта, результатов меньше двух или ещё идут попытки в счётчике (`matches`).

Ответ `{ "tournament": Tour }`.

`fee` — взнос, ₽ (`null` — без взноса), виден всем; `cover` — общее фото игроков `{ id, url, w, h }` или `null`; у сыгранного турнира ещё `best: { avg: { id, name, v }, hco: { id, name, v }, c180: { total, top: { id, name, n } } }` — лучшее среднее за матч (от 9 дротиков), максимальное закрытие и 180. `can.staff` — организатор или помощник клуба; `can.fees` — взносы (команда турнира с тарифом «Ведущий»), только тогда в ответе `fees`. `org.logo` — логотип клуба с тарифом «Ведущий». В `POST` и `PATCH` турнира — `fee` (взнос, ₽, 0–100000 или `null` — без взноса; любой организатор), его можно менять и после старта.

### `PATCH /api/tournaments/:id/cover` — организатор
`{ "photoId": "…" }` — общее фото игроков из фото турнира (`404`, если фото чужое), `null` — убрать. Удалили фото — общего фото нет. Ответ `{ tournament }`.

### `PATCH /api/tournaments/:id/paid` — команда турнира, `can.fees`
`{ "playerId", "paid": true | false }` — отметка «оплатил». Ответ `{ tournament }`.

### `PATCH /api/tournaments/:id/boards` — организатор или помощник, до старта и во время турнира
- `{ "n": 6 }` — сколько мишеней, номера 1…6 (0 — без мишеней);
- `{ "names": [3, 5, 7] }` — номера мишеней в зале (до 64 разных чисел 1–999, `[]` — убрать);
- `{ "r": 1, "i": 3, "board": 2 }` — поставить готовой игре мишень (порядковый номер 1…n); у другой игры она снимается, та получает свободную. Только после старта.

Мишени можно указать и при создании: `POST /api/tournaments` с `"boards": [1, 2, 3, 4]`. После старта игры и квалификация распределяются сами. `409 bad_state` — игра не готова или турнир завершён. Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/games/:r/:i/ready` — игрок пары готовой игры
`{ "on": true }` (по умолчанию) — «Готов, я у мишени», `{ "on": false }` — снять отметку. Когда готовы оба, матч начинается сам: счёт ведёт телефон того, кто отметился вторым (`lock.mine`); другой видит матч идущим и может забрать ведение (`/takeover`). Ответ `{ "ready": ["p5"], "match": Match | null }`. `403` — не игрок этой пары, `409 game_taken` — матч уже идёт, `409 bad_state` — игра не готова.

### `PATCH /api/tournaments/:id/streams` — организатор-ведущий (`can.stream`), в любой момент
Камеры: `{ "streams": [{ "title": "Камера 1", "url": "https://vk.com/video-123_456", "boards": [1, 2] }] }` — до 4, ссылка `https` (трансляция VK, YouTube, RuTube или адрес из кода вставки), `boards` — какие мишени снимает камера (может быть пусто — общий план). Без `title` — «Камера N». Ответ `{ "tournament": Tour }`; в `Tour` — поле `streams`.

### `PATCH /api/tournaments/:id/links` — организатор, в любой момент
`{ "links": [{ "title": "Трансляция", "url": "https://vk.com/video…" }] }` — до 20 ссылок, только `http(s)`; без `title` подписью станет домен. Ответ `{ "tournament": Tour }`.

### `PATCH /api/tournaments/:id/nums` — организатор
`{ "nums": { "p5": 7 } }` — поменять номера (1–999), остальные остаются; `{ "nums": null }` — номера по порядку. Ответ `{ "tournament": Tour }`.

## Матчи (счётчик)

Матч, который ведётся в счётчике, — это последовательность событий. Телефон маркера отправляет их **по одному и по порядку** через очередь неотправленного (подробнее в `docs/server-load.md`).

**id матча придумывает телефон** до первой отправки: `g` + 10–30 символов `[a-z0-9]`, как сейчас в `newGame()`. Поэтому очередь работает даже без сети с самого начала дружеской игры.

### `PUT /api/matches/:id` — нужен вход
Начать матч. Турнирный:
```json
{ "tournamentId": "t4", "r": 1, "i": 3, "starter": 0 }
```
Дружеский:
```json
{ "mode": 501, "ltw": 2, "dbl": true, "starter": 0, "players": [{ "id": "p5" }, { "name": "Гость" }] }
```
Дружеский с упражнением: `{ "ex": { "k": "cricket", "lim": 10 }, "ltw": 1, "players": […] }`.

Попытка квалификации (сдаёт сам игрок или организатор, при `stage: qual`):
```json
{ "tournamentId": "t11", "qual": { "playerId": "p5", "try": 0 } }
```
Один игрок, один лег упражнения квалификации. После `finish` итог лега записывается в `qual.res`; если квалификацию уже закрыли или результат внесли вручную, матч остаётся тренировкой.
- В турнирном матче игроки и настройки берутся из турнира, порядок игроков — как в сетке (`a`, `b`). Нужно право `can.score`.
- Дружеский матч: 1–4 игрока, хотя бы один с `id`.
- Устройство, начавшее матч, получает **замок**: только оно может отправлять события.
- Повтор того же запроса с того же устройства возвращает тот же матч (`200`), поэтому его можно безопасно отправить ещё раз.

Ошибки:
- `409 game_taken` с `matchId` — эту игру сетки уже ведёт или сыграл другой матч;
- `409 bad_state` — игра не готова.

Ответ `201 { "match": Match }`.

### `POST /api/matches/:id/events` — устройство с замком
```json
{ "events": [
  { "seq": 1, "type": "visit", "leg": 1, "p": 0, "s": 501, "pts": 100, "n": 3, "b": 0, "d": null },
  { "seq": 2, "type": "undo" },
  { "seq": 3, "type": "finish", "w": 0, "pl": [Line, Line] }
] }
```
- `seq` — 1, 2, 3, … без пропусков. За раз 1–50 событий.
- **`visit`** — это запись `G.log` из счётчика:
  - `p` — индекс игрока;
  - `s` — остаток до подхода;
  - `pts` — очки (при переборе 0);
  - `n` — дротиков;
  - `b` — перебор (1/0);
  - `d` — метки дротиков (`["T20","T20","D20"]`) или `null` при вводе суммой.
- **`undo`** — отменить последний неотменённый подход.
- **`finish`** — конец матча: `w` — индекс победителя, `pl` — итоговая статистика из `commitMatch()`.
- **`visit` в упражнениях** (`ex` не x01): `{ "seq": 4, "type": "visit", "leg": 1, "p": 0, "v": 100, "d": null }`:
  - `v` — очки подхода (`score`) или попадания в цель подхода (`round`, `sector`);
  - `d` — метки дротиков (`["T20", "20", "0"]`), необязательны, но должны давать `v`; у крикета обязательны (`v` не нужно), меньше 3 дротиков — только когда подход выигрывает лег.
- **`bull`** — ничья в леге без закрытия: `{ "seq": 41, "type": "bull", "leg": 2, "p": 0 }` — игрок `p` выиграл бросок в булл и лег. Принимается только при ничьей (`state.tie`).
- В `finish` у упражнений `pts` и `darts` — как считает `Games.state()`: `pts` — очки (у сектора попадания, у крикета метки).

Сервер проверяет:
- событие с уже принятым `seq` пропускается без ошибки, так что повторная отправка безопасна;
- `seq` больше ожидаемого → `409 seq_gap` с `expectSeq`: дослать с этого номера;
- подход сходится со счётом: верный игрок по очереди, `s` равен остатку, очки 0–180 и не из невозможных (163, 166, 169, 172, 173, 175, 176, 178, 179), закрытие допустимо → иначе `422 bad_event` с `seq`;
- в `finish` леги и сумма очков и дротиков совпадают с подходами;
- замок у другого устройства → `423 locked` с `by` (имя) и `until`.

Ответ:
```json
{ "ok": true, "seq": 3, "version": 15 }
```
Пачка принимается целиком или не принимается совсем. При `422` очередь останавливается: показать «Счёт не принят сервером», забрать события через `takeover` и восстановить счётчик по ним.
`seq` — последний принятый номер. Каждое принятое событие продлевает замок на 10 минут.

После `finish` результат попадает в сетку, а рейтинг и статистика пересчитываются.

### `POST /api/matches/:id/takeover` — `can.score` турнира или участник дружеского матча
Забрать ведение счёта на это устройство. Ответ `{ "match": Match, "events": [Event] }` — все события, чтобы восстановить счётчик. Следующий `seq` = последний + 1.

### `POST /api/matches/:id/reopen` — устройство с замком
Отменить завершение (кнопка «Отменить» сразу после конца матча). Матч снова `live`, результат снимается с сетки. Сервер сам добавляет событие `reopen`, поэтому следующий `seq` = `match.lastSeq` + 1.
- `409 result_locked` — следующие матчи сетки уже сыграны или идут.
- Вызывать только когда очередь неотправленного пуста.

Ответ `{ "match": Match }`.

### `DELETE /api/matches/:id`
- Идущий матч: бросить (устройство с замком или организатор). Игра сетки снова свободна.
- Сыгранный турнирный матч: снять результат (организатор). При `409 result_locked` — как в `reopen`.

Ответ `{ "ok": true }`.

### `GET /api/matches/:id?since=15`
Для зрителей и протокола.
- После версии 15 ничего не изменилось — `204`.
- Иначе:
  ```json
  { "match": Match, "events": [Event], "version": 18 }
  ```
  `events` — только события новее `since`; без `since` — все.

**`Match`:**
```json
{ "id": "gq7p0c2mzt", "status": "live", "tid": "t4", "r": 1, "i": 3, "mode": 501, "ltw": 3, "dbl": true, "starter": 0,
  "players": [{ "id": "p1", "name": "Артём Волков" }, { "id": "p8", "name": "Павел Зуев" }],
  "legs": [1, 0], "w": null, "state": { "leg": 2, "cur": 1, "scores": [321, 441], "avg": [88.4, 71.2], "last": { "p": 0, "pts": 180, "n": 3, "b": 0, "d": ["T20", "T20", "T20"] } },
  "lastSeq": 14, "version": 15, "started": 1760000000000, "finished": null,
  "lock": { "mine": false, "by": "Денис Карпов", "until": 1760000600000 }, "card": null }
```
- `status` — `live` или `done`.
- `legs` — выигранные леги (сервер считает по подходам).
- `state` — живой счёт:
  - `leg` — номер лега;
  - `cur` — кто бросает (`null`, когда матч выигран);
  - `scores` — остатки;
  - `last` — последний подход или `null`.
- `card` — `MatchCard` после `finish`.
- `ex` — упражнение или `null`; `q` — попытка квалификации `{ "id", "k" }` или `null`.
- `state.avg` — средний за подход (3 дротика) по всему матчу, `null` без бросков.
- У упражнений в `state`: `scores` — счёт лега (очки, попадания, очки крикета; у x01 — остатки), `vis` — подходов в леге у каждого, `marks` — метки крикета `[{ "20": 3, … }]`, `tie` — кто разыгрывает булл (тогда `cur: null`); у `last` бывает `{ "p": 0, "tb": 1 }`.
- **`Event`** — то же, что в `/events`, плюс поле `t` (время приёма). Бывает ещё тип `reopen` (см. выше).

Счёт у зрителя можно брать из `state` или считать по подходам: остаток = `mode` − сумма `pts` игрока в текущем леге. Первым в леге `k` бросает игрок `(starter + k − 1) mod число игроков`.

## Табло (живой счёт без задержки)

Для телевизора у организатора и для страницы турнира. Сервер сам присылает изменения через Server-Sent Events, через 50–100 мс после записи подхода. Опрашивать ничего не нужно.

### `GET /api/tournaments/:id/live`
Снимок без потока:
```json
{ "version": 57, "matches": [LiveMatch] }
```
`version` — версия турнира, `matches` — идущие матчи.

**`LiveMatch`**:
```json
{ "id": "gq7p0c2mzt", "r": 1, "i": 3, "status": "live", "mode": 501, "ltw": 3,
  "players": [{ "id": "p1", "name": "Артём Волков" }, { "id": "p8", "name": "Павел Зуев" }],
  "legs": [1, 0], "w": null, "state": { "leg": 2, "cur": 1, "scores": [321, 441], "avg": [88.4, 71.2], "last": { "p": 0, "pts": 180, "n": 3, "b": 0, "d": null } },
  "version": 15, "lastSeq": 14, "by": "Денис Карпов" }
```
`by` — кто ведёт счёт. `ex` и `q` — как у `Match`: попытки квалификации тоже идут в поток (у них `r` и `i` равны `null`).

### `GET /api/tournaments/:id/stream?d=устройство` — поток `text/event-stream`
`d` — тот же id устройства, что в `X-Device-Id` (`EventSource` не умеет слать заголовки): по нему считается ограничение частоты. Без `d` лимит общий на IP, а в зале все телефоны в одном Wi-Fi выходят с одного адреса.

События:

| `event` | `data` | Что делать |
|---|---|---|
| `snapshot` | как у `/live` | приходит сразу при подключении и после сбоя связи сервера с базой; заменить всё |
| `match` | `LiveMatch` | матч начался, новый подход, отмена, завершение (`status: "done"`); заменить матч по `id`, если `version` новее |
| `match` | `{ "id": "…", "deleted": true }` | матч брошен или результат снят: убрать с табло |
| `tour` | `{ "version": 58 }` | изменилась сетка: один раз запросить `GET /api/tournaments/:id` |
| `tour` | `{ "deleted": true }` | турнир удалён |

Пример:
```js
const es = new EventSource('/api/tournaments/' + id + '/stream');
es.addEventListener('snapshot', e => showAll(JSON.parse(e.data)));
es.addEventListener('match', e => showMatch(JSON.parse(e.data)));   // анимация 180, перебора и закрытия — по state.last
es.addEventListener('tour', () => reloadBracket());
```
- `EventSource` сам переподключается при обрыве: через 3 с, сервер задаёт это в `retry`. После переподключения снова приходит `snapshot`.
- Если табло открыто, сетку можно обновлять по событию `tour` вместо опроса раз в 30 с.
- На телефонах, где поток не держится (свёрнутая вкладка), достаточно опроса `GET /api/tournaments/:id?since=` раз в 30 с.

## Права

| Действие | Кто может |
|---|---|
| Смотреть всё | все, без входа |
| Создать турнир, гостя, дружеский матч, подать заявку на клуб | вошедший |
| Изменить и удалить турнир, запустить, записать другого | организатор, администратор |
| Записаться и отписаться самому | вошедший, пока идёт регистрация |
| Вести счёт турнирного матча | организатор турнира или игрок этой пары, администратор |
| Снять результат | организатор, администратор |
| Турнир от имени клуба, камеры, свои номера игроков, аккаунты с кодом входа | ведущий |
| Все игроки: правка, подтверждение, блокировка, роль ведущего; клубы и их ведущие; любой турнир; сводка | администратор |
| Роли администратора и тех. администратора, логины и пароли администраторов, права ролей | тех. администратор |

Права ведущего и администратора выше — по умолчанию; тех. администратор меняет их во вкладке «Права ролей» (`/api/admin/perms`).

Без входа дружеские игры работают как сейчас: остаются на телефоне и на сервер не отправляются.

## Что серверу нужно из `shared/bracket.js`

Эти функции должны работать без DOM и без глобального состояния страницы:

- `resolver`, `gameAt`, `gameState`, `gameNums`, `tProgress`;
- `tStatus`, `champion`, `placeRange`, `standings`;
