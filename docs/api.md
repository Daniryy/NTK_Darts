# Oche API

Договор между страницей и сервером. Сначала меняем здесь, потом в коде.

## Общее

- Адрес: `/api/...`, данные в JSON (`Content-Type: application/json`).
- Время — миллисекунды с 1970 года (как `Date.now()`).
- Идентификаторы — строки: игроки `p…`, турниры `t…`. Матч получает id от телефона (см. «Матчи»).
- **Устройство.** Каждый запрос на запись содержит заголовок `X-Device-Id`. Это случайная строка из 16–64 символов `[A-Za-z0-9_-]`, её один раз создают и хранят в `localStorage['oche.device']`. По ней работают замок матча и ограничение частоты.
- **Вход.** Сессия хранится в httpOnly-cookie `oche_sid`, её ставит сервер. Без входа доступно только чтение.
- **Ограничение частоты:** 10 запросов в секунду с устройства, кратковременно до 20. При превышении — `429` и заголовок `Retry-After`.
- **Ошибка** всегда приходит в таком виде:
  ```json
  { "error": { "code": "seq_gap", "message": "Ожидается подход №12", "expectSeq": 12 } }
  ```

| HTTP | code | Когда |
|---|---|---|
| 400 | `bad_request` | неверные поля; в `fields` указано, какие |
| 401 | `unauthorized` | нужен вход |
| 403 | `forbidden` | нет прав |
| 404 | `not_found` | нет такого объекта |
| 409 | `conflict`, `seq_gap`, `game_taken`, `result_locked`, `bad_state` | конфликт состояния, подробности в полях ошибки |
| 422 | `bad_event` | подход не сходится со счётом |
| 423 | `locked` | матч ведёт другое устройство |
| 429 | `too_many` | слишком часто |
| 500 | `server` | ошибка сервера |

## Вход и профиль

### `GET /api/auth/vk?return=/путь`
Переход на страницу входа VK. После входа VK возвращает на `/api/auth/vk/callback`, сервер ставит cookie и перенаправляет на `return`. Страница делает обычную ссылку на этот адрес.

### `GET /api/config`
Что умеет сервер: `{ "vk": true, "dev": false }` — настроен ли вход через VK, доступен ли вход для разработки.

### `POST /api/auth/logout`
Выход. Ответ `{ "ok": true }`.

### `POST /api/auth/dev` — только при `NODE_ENV=development`
Тело `{ "playerId": "p3" }`. Вход без VK для разработки.

### `GET /api/me`
```json
{ "player": { "id": "p17", "name": "Иван Петров", "handle": "ivan_p", "code": "OCH-4821", "city": "Москва", "club": "«Оче-бар»", "ver": false },
  "admin": false }
```
Если вход не выполнен, приходит `{ "player": null, "admin": false }`, а не ошибка.

### `PATCH /api/me`
Тело `{ "name"?, "city"?, "club"?, "title"? }`. Ограничения: `name` 2–32 символа, `city`, `club` и `title` (разряд или звание) до 40. Ответ — как у `GET /api/me`.

### `POST /api/me/claim`
Привязать аккаунт, созданный администратором: `{ "code": "K7MQ2XRA" }` (регистр, пробелы и дефисы не важны). Сессия переходит к тому аккаунту, VK — тоже; свой пустой аккаунт удаляется.
- `404` — кода нет (код одноразовый);
- `409 conflict` — у своего аккаунта уже есть матчи или турниры, или тот аккаунт уже привязан к VK.

Ответ — как у `GET /api/me`.

## Фото

Страница сама обрезает и сжимает картинку (аватар — квадрат, итоги — 4:3) и присылает готовый файл.

### `POST /api/photos?kind=avatar[&playerId=p5]&w=400&h=400` — нужен вход
### `POST /api/photos?kind=tour&tournamentId=t4&w=1280&h=960` — организатор
Тело — сама картинка, `Content-Type: image/jpeg | image/webp | image/png`, до 3 МБ. `w`, `h` — размер в точках (16–4096).
- Аватар: свой; гостя, которого создал я; любой — администратору. Новый заменяет старый.
- Итоги турнира: до 60 фото, меняет версию турнира.

Ответ `201 { "photo": { "id": "…", "url": "/uploads/….jpg", "w": 400, "h": 400 }, "player": PlayerShort }` (`player` — у аватара).

### `DELETE /api/players/:id/photo`
Убрать аватар игрока (права — как на загрузку). Ответ `{ "ok": true }`.

### `DELETE /api/photos/:id`
Свой аватар, аватар своего гостя, фото турнира — организатор; администратор — любое. Ответ `{ "ok": true }`.

## Администратор

### `GET /api/admin/players?q=&limit=50`
Игроки с полями `vk` (привязан ли VK), `claim` (код привязки или `null`), `admin`, `owner`. Ответ `{ "players": [...] }`.

### `POST /api/admin/players`
`{ "name", "city"?, "club"?, "title"? }` — новый аккаунт с кодом привязки. Код отдают игроку: он входит через VK и вводит код в профиле. Ответ `201 { "player": … }`.

### `PATCH /api/admin/players/:id`
`{ "name"?, "city"?, "club"?, "title"?, "ver"?, "admin"?, "claim": true | false }` — правка; `claim: true` — новый код, `false` — убрать. Ответ `{ "player": … }`.

## Игроки

**Карточка игрока** (`PlayerShort`):
```json
{ "id": "p3", "name": "Марина Соколова", "handle": "sokolova_m", "code": "OCH-1003", "city": "Казань", "club": "«Бычий глаз»", "ver": true, "r": 1612, "n": 41,
  "photo": "/uploads/….jpg", "title": "КМС" }
```
`photo` — аватар или `null`, `title` — разряд или звание. Те же поля есть у `GET /api/me`, в `roster` турнира и в строках рейтинга (`photo`).
`r` — рейтинг, `n` — число турнирных матчей в рейтинге.

### `GET /api/players?q=текст&limit=20`
Поиск по имени, `@handle` и коду (`OCH-1003`, `#1003`). Ответ `{ "players": [PlayerShort] }`, не больше 50.

### `POST /api/players` — нужен вход
Тело `{ "name": "Гость Сергей", "city": "Москва" }`. Создаёт игрока без VK, чтобы добавить его в турнир. Если у этого же организатора уже есть игрок без VK с таким именем, возвращает его. Ответ `{ "player": PlayerShort }`.

### `GET /api/players/:id`
```json
{
  "player": PlayerShort,
  "rank": 12,
  "stats": { "all": Stats, "tour": Stats },
  "matches": [MatchCard],
  "tournaments": [{ "id": "t9", "name": "…", "start": 1760000000000, "status": "done", "format": "pl", "place": [3, 3] }]
}
```
- `rank` — место в рейтинге, или `null`.
- `matches` — последние 50.
- `place` — `[от, до]` или `null` (идёт регистрация).
- `Stats`:
  ```json
  { "n": 41, "w": 25, "pts": 30120, "darts": 1215, "avg": 74.4, "f9": 81.2, "coh": 60, "coa": 171, "hco": 121, "hi": 180, "c180": 6, "c140": 31, "c100": 118, "bl": 15 }
  ```
  Поля те же, что у `pStats()` на странице: `c140` включает 180, а `c100` включает 140+. `avg` и `f9` равны `null`, если бросков нет.

### `GET /api/players/:id/matches?scope=all|tour&before=время&limit=50`
Следующая страница матчей. Ответ `{ "matches": [MatchCard] }`.

## Рейтинг и лента

### `GET /api/rating?sort=r|avg&city=Москва&q=текст&limit=50&offset=0`
```json
{ "total": 312, "cities": ["Москва", "Казань"],
  "rows": [{ "rank": 1, "id": "p1", "name": "Артём Волков", "city": "Москва", "club": "…", "r": 1704, "avg": 87.9, "n": 52 }] }
```
Рейтинг Эло только по турнирным матчам: старт 1500, коэффициент 32, как в `recalc()`. Игроки без турнирных матчей в таблицу не попадают.

### `GET /api/feed?scope=all|my&before=время&limit=30`
```json
{ "items": [
  { "type": "match", "t": 1760000000000, "match": MatchCard },
  { "type": "tournament", "t": 1760000000000, "tournament": TourCard }
] }
```
- `type: "tournament"` — турнир завершён, у `TourCard` есть `champion`.
- `my` — только с моим участием (нужен вход).
- Следующая страница — `before` = `t` последнего элемента.

**`MatchCard`** — то же, что объект матча на странице:
```json
{ "id": "g8x2k1q9zp", "t": 1760000000000, "tid": "t4", "tname": "Кубок Лиги · этап 4", "r": 2, "i": 0, "label": "круг 3 · за 1–4 места", "off": true,
  "mode": 501, "ltw": 3, "dbl": true, "w": 0, "quick": false,
  "pl": [ Line, Line ] }
```
- `tid`, `tname`, `r`, `i`, `label` равны `null` у дружеских матчей. `label` — подпись игры, как `gameLabel()` на странице.
- `quick: true` — счёт внесён без бросков: у строк `pts` и `darts` равны 0, `f9` равно `null`.
- `Line`: `{ "id": "p1"|null, "n": "имя", "legs": 3, "pts": 1203, "darts": 48, "f9": 92.1, "hi": 140, "hco": 81, "c180": 1, "c140": 3, "c100": 8, "coh": 3, "coa": 7, "bl": 15 }`. У гостя `id: null`.
- Протокол с подходами — `GET /api/matches/:id`.
- `ex` — упражнение (см. «Упражнения»), `null` у обычного x01. `q` — `{ "id": "p5", "k": 0 }` у попытки квалификации (`label`: «квалификация · попытка 1»), иначе `null`. Попытки квалификации в ленту не попадают.
- У строк упражнений `sc` — итоги легов (`[845, 790]`), у x01 `null`. `pts` и `darts` — очки (у «Сектора» — попадания, у крикета — метки) и дротики за матч: средний за подход = `pts / darts × 3`. В статистику игрока (средние x01) упражнения не входят.

## Упражнения

Матч состоит из легов, лег — одно упражнение. Правила и счёт — в общем модуле `shared/games.js` (страница и сервер считают одинаково).

**`Ex`:**
```json
{ "k": "x01", "mode": 501, "dbl": true, "lim": 10 }
{ "k": "score", "lim": 10 }
{ "k": "round" }
{ "k": "sector", "sec": 20, "lim": 10 }
{ "k": "cricket", "lim": 10 }
```
- `x01` — до нуля; `lim` — подходов на игрока в леге (0 — без ограничения). Обычный x01 без лимита в API — `ex: null` и поля `mode`, `dbl`.
- `score` — «Набор очков»: сумма за `lim` подходов.
- `round` — «Большой раунд»: 21 подход — сектора 1…20 и булл; очки = попадания в нужный сектор × номер сектора (дубль — 2 попадания, трипл — 3; 25 — 1, булл — 2, по 25).
- `sector` — «Сектор `sec`»: число попаданий за `lim` подходов (дубль — 2, трипл — 3).
- `cricket` — 15–20 и булл; лег выигрывает тот, кто закрыл всё и не отстаёт по очкам; `lim` — подходов на игрока (0 — до закрытия).
- **Лег без закрытия** (кончился лимит подходов): выигрывает меньший остаток (x01), больше очков (крикет: затем больше меток) или больше результат. При равенстве — бросок в булл: событие `bull`.
- Лег `k` начинает игрок `(starter + k − 1) mod число игроков`, бросают по очереди.

## Турниры

**`Tour`** — турнир в том же виде, в котором страница хранит его сейчас. Плюс поля `version`, `live`, `roster`, `can`:
```json
{
  "id": "t4", "name": "Кубок Лиги · этап 4", "official": true,
  "org": { "id": "p1", "name": "Лига Oche", "ver": true },
  "city": "Москва", "venue": "Клуб «Тройная двадцатка»",
  "start": 1760000000000, "regUntil": null, "status": "live",
  "format": "pl", "mode": 501, "ltw": 3, "dbl": true, "cap": 16,
  "players": ["p1", "p2"],
  "slots": ["p1", null, "p8"],
  "games": [{ "r": 0, "i": 0, "res": { "la": 3, "lb": 1, "w": "p1", "mid": "g8x2k1q9zp" } }, { "r": 0, "i": 1, "res": null }],
  "live": { "0:1": "gq7p0c2mzt" },
  "roster": { "p1": { "name": "Артём Волков", "city": "Москва", "club": "…", "r": 1704 } },
  "version": 57,
  "can": { "edit": false, "delete": false, "launch": false, "score": true, "join": false }
}
```
- **`status`:**
  - `reg` — идёт регистрация;
  - `live` — идёт;
  - `done` — все матчи сыграны (сервер считает так же, как `tStatus()`).
- **`slots`** — только у `pl` и `ko`. Это посев: `null` значит свободное место.
- **`games`:**
  - в `pl` и `ko` это все игры сетки (`r`, `i`, `res`), кругом за кругом;
  - в `rr` у каждой игры также есть `a` и `b`;
  - при регистрации `games: []`;
  - сетку, номера, места и подписи страница считает сама через `shared/bracket.js`.
- **`live`** — какие игры сейчас идут: `"r:i"` → id матча; попытки квалификации — `"q:p5:0"` → id матча.
- **`ex`** — упражнение матчей (`Ex`), нет поля — обычный x01 по `mode` и `dbl`.
- **Квалификация** (формат NDL):
  - `qual` — `{ "ex": Ex, "tries": 2, "res": { "p5": [{ "v": 845, "mid": "g…", "t": 1760000000000 }, null] } }`: упражнение, сколько попыток, результаты (`mid` — матч счётчика или `null`, если внёс организатор);
  - `stage: "qual"` — квалификация идёт, сетки ещё нет (`games: []`, `slots` нет);
  - после закрытия места 1–`split` играют первую часть сетки, следующие — вторую и т. д.
- **`split`** — размер части сетки (8 у NDL). **`block`** — части построенной сетки: `slots` идут частями по `block`, номер игры `i` сквозной (см. `shared/bracket.js`). Нет `block` — сетка одна.
- **`res.avg`** — средний набор игроков за подход в сыгранной игре: `[a, b]`, `null` без бросков.
- **`boards`** — мишени: `{ "n": 6, "at": { "1:3": 2 } }` — сколько их и у какой готовой игры какая. Сыгранная игра освобождает мишень, свободные получают готовые игры по порядку номеров.
- **`photos`** — фото к итогам `[{ "id", "url", "w", "h" }]`, **`links`** — ссылки `[{ "title", "url" }]`.
- **`nums`** — номера игроков в турнире `{ "p5": 7 }`; нет поля — номер = позиция в `players` + 1. После квалификации номер = место в квалификации.
- **`roster`** — данные всех участников, чтобы не запрашивать их отдельно.
- **`can`** — что разрешено текущему пользователю:
  - `org` — текущий пользователь организатор (или админ): квалификация, мишени, номера;
  - `edit`, `delete`, `launch` — организатору;
  - `score` — вести счёт в этом турнире;
  - `join` — можно записаться или отписаться.

**`TourCard`** — для списков:
```json
{ "id": "t4", "name": "…", "official": true, "org": { "id": "p1", "name": "…", "ver": true }, "city": "Москва", "venue": "…",
  "start": 1760000000000, "regUntil": null, "status": "live", "format": "pl", "mode": 501, "ltw": 3, "cap": 16,
  "count": 16, "progress": { "done": 18, "total": 32 }, "champion": null, "joined": true, "version": 57,
  "ex": null, "qual": null, "split": null, "stage": null }
```
Во время квалификации `progress` — сколько игроков сдали из всех.

### `GET /api/tournaments?status=reg|live|done&city=&q=&mine=1&limit=30&offset=0`
Ответ `{ "total": 12, "tournaments": [TourCard] }`. `mine=1` — я участник или организатор (нужен вход).

### `GET /api/tournaments/:id?since=57`
- Изменений после версии 57 нет — `204` без тела.
- Есть — `{ "tournament": Tour }`, целиком: он маленький (до 15 КБ), почти все опросы получают `204`.

Версия растёт, когда:
- меняется запись участников или настройки;
- турнир запускается;
- матч начинается, заканчивается или отменяется.

Отдельные подходы версию турнира **не** меняют.

### `POST /api/tournaments` — нужен вход
```json
{ "name": "Мой турнир", "city": "Москва", "venue": "«Оче-бар»", "format": "pl", "mode": 501, "ltw": 2, "seed": "r",
  "players": ["p1", "p5", "p9"], "reg": false, "regUntil": null, "cap": null, "start": null }
```
- `reg: false` — сразу запуск: сервер делает посев (`seed: r` по рейтингу, `x` жеребьёвкой) и строит сетку.
- `reg: true` — открыть регистрацию; `players` можно не передавать, `cap` (лимит мест) обязателен.
- `ex` — упражнение матчей (`Ex`); тогда `mode` можно не передавать. `ex: { k: "x01", … }` без лимита сохраняется как обычный `mode`/`dbl`.
- **NDL:** `format: "pl"`, `qual: { "ex": { "k": "score" }, "tries": 2 }` и `split: 8` (по умолчанию 8). Запуск открывает квалификацию (`stage: "qual"`), порядок `players` — как прислали (это номера до квалификации). Упражнение квалификации — `score`, `round` или `sector`.
- `split` без `qual` — сетка частями по посеву (места 1–8, 9–16…).

Только администратор может передать `official`, `orgName`, `orgVer` (официальный турнир от имени клуба или лиги).

Ограничения:

| Поле | Допустимые значения |
|---|---|
| `name` | 1–60 символов |
| `venue` | до 60 символов |
| `city` | до 40 символов |
| `format` | `pl`, `ko`, `rr`; `qual` и `split` — только `pl` |
| `mode` | 301, 501, 701 |
| `split` | 4, 8, 16, 32 |
| `qual.tries` | 1–2 |
| `ltw` | 1–5 |
| участники | `pl`/`ko` — 3–64, `rr` — 3–10, без повторов |

Ответ `201 { "tournament": Tour }`.

### `PATCH /api/tournaments/:id` — организатор, только при `status: reg`
Любые поля из создания, кроме `players`. Ответ `{ "tournament": Tour }`.

### `DELETE /api/tournaments/:id` — организатор
Удаляет турнир и его матчи. Ответ `{ "ok": true }`.

### `POST /api/tournaments/:id/entries` — при `status: reg`
Тело `{ "playerId": "p5" }`:
- без тела — записать себя;
- с `playerId` — организатор записывает любого.

Ошибки:
- `409 conflict` с `"reason": "full"` — нет мест;
- `409 conflict` с `"reason": "already"` — игрок уже записан.

Ответ `{ "tournament": Tour }`.

### `DELETE /api/tournaments/:id/entries/:playerId` — себя или организатор, при `status: reg`
Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/launch` — организатор
Закрыть регистрацию и построить сетку (посев по рейтингу). Если участников меньше 3 или больше лимита формата — `409 bad_state`. Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/games/:r/:i/result` — `can.score`
Быстрый счёт без бросков: `{ "la": 3, "lb": 1 }`. Победитель должен выиграть ровно `ltw` легов.

Ошибки:
- `409 game_taken` с `matchId` — игра идёт или уже сыграна;
- `409 bad_state` — игра ещё не готова (соперник не определён).

Ответ `{ "tournament": Tour, "match": MatchCard }`.

### `PUT /api/tournaments/:id/qual/:playerId/:try` — организатор, при `stage: qual`
Результат попытки вручную: `{ "v": 845 }`. `try` — с 0; попытка `k` — только после попытки `k − 1`. `v` — от 0 до максимума упражнения (`score` — 180 × `lim`, `round` — 2040, `sector` — 9 × `lim`).

Ошибки:
- `409 game_taken` — попытка идёт или сыграна в счётчике;
- `409 bad_state` — нет предыдущей попытки или квалификация закрыта.

Ответ `{ "tournament": Tour }`.

### `DELETE /api/tournaments/:id/qual/:playerId/:try` — организатор, при `stage: qual`
Удалить результат этой и следующих попыток (вместе с их матчами). Ответ `{ "tournament": Tour }`.

### `POST /api/tournaments/:id/qual/close` — организатор
Закончить квалификацию: порядок по лучшему результату, затем по второй попытке, затем по рейтингу (кто не сдал — в конце). Сетка строится частями по `split` мест, `nums` — места квалификации.
- `409 bad_state` — квалификация уже закрыта, результатов меньше двух или ещё идут попытки в счётчике (`matches`).

Ответ `{ "tournament": Tour }`.

### `PATCH /api/tournaments/:id/boards` — организатор, после старта
- `{ "n": 6 }` — сколько мишеней (0 — без мишеней);
- `{ "r": 1, "i": 3, "board": 2 }` — поставить готовой игре мишень; у другой игры она снимается, та получает свободную.

`409 bad_state` — игра не готова. Ответ `{ "tournament": Tour }`.

### `PATCH /api/tournaments/:id/streams` — организатор, в любой момент
Камеры: `{ "streams": [{ "title": "Камера 1", "url": "https://vk.com/video-123_456", "boards": [1, 2] }] }` — до 4, ссылка `https` (трансляция VK, YouTube, RuTube или адрес из кода вставки), `boards` — какие мишени снимает камера (может быть пусто — общий план). Без `title` — «Камера N». Ответ `{ "tournament": Tour }`; в `Tour` — поле `streams`.

### `PATCH /api/tournaments/:id/links` — организатор, в любой момент
`{ "links": [{ "title": "Трансляция", "url": "https://vk.com/video…" }] }` — до 20 ссылок, только `http(s)`; без `title` подписью станет домен. Ответ `{ "tournament": Tour }`.

### `PATCH /api/tournaments/:id/nums` — организатор
`{ "nums": { "p5": 7 } }` — поменять номера (1–999), остальные остаются; `{ "nums": null }` — номера по порядку. Ответ `{ "tournament": Tour }`.

## Матчи (счётчик)

Матч, который ведётся в счётчике, — это последовательность событий. Телефон маркера отправляет их **по одному и по порядку** через очередь неотправленного (подробнее в `docs/server-load.md`).

**id матча придумывает телефон** до первой отправки: `g` + 10–30 символов `[a-z0-9]`, как сейчас в `newGame()`. Поэтому очередь работает даже без сети с самого начала дружеской игры.

### `PUT /api/matches/:id` — нужен вход
Начать матч. Турнирный:
```json
{ "tournamentId": "t4", "r": 1, "i": 3, "starter": 0 }
```
Дружеский:
```json
{ "mode": 501, "ltw": 2, "dbl": true, "starter": 0, "players": [{ "id": "p5" }, { "name": "Гость" }] }
```
Дружеский с упражнением: `{ "ex": { "k": "cricket", "lim": 10 }, "ltw": 1, "players": […] }`.

Попытка квалификации (сдаёт сам игрок или организатор, при `stage: qual`):
```json
{ "tournamentId": "t11", "qual": { "playerId": "p5", "try": 0 } }
```
Один игрок, один лег упражнения квалификации. После `finish` итог лега записывается в `qual.res`; если квалификацию уже закрыли или результат внесли вручную, матч остаётся тренировкой.
- В турнирном матче игроки и настройки берутся из турнира, порядок игроков — как в сетке (`a`, `b`). Нужно право `can.score`.
- Дружеский матч: 1–4 игрока, хотя бы один с `id`.
- Устройство, начавшее матч, получает **замок**: только оно может отправлять события.
- Повтор того же запроса с того же устройства возвращает тот же матч (`200`), поэтому его можно безопасно отправить ещё раз.

Ошибки:
- `409 game_taken` с `matchId` — эту игру сетки уже ведёт или сыграл другой матч;
- `409 bad_state` — игра не готова.

Ответ `201 { "match": Match }`.

### `POST /api/matches/:id/events` — устройство с замком
```json
{ "events": [
  { "seq": 1, "type": "visit", "leg": 1, "p": 0, "s": 501, "pts": 100, "n": 3, "b": 0, "d": null },
  { "seq": 2, "type": "undo" },
  { "seq": 3, "type": "finish", "w": 0, "pl": [Line, Line] }
] }
```
- `seq` — 1, 2, 3, … без пропусков. За раз 1–50 событий.
- **`visit`** — это запись `G.log` из счётчика:
  - `p` — индекс игрока;
  - `s` — остаток до подхода;
  - `pts` — очки (при переборе 0);
  - `n` — дротиков;
  - `b` — перебор (1/0);
  - `d` — метки дротиков (`["T20","T20","D20"]`) или `null` при вводе суммой.
- **`undo`** — отменить последний неотменённый подход.
- **`finish`** — конец матча: `w` — индекс победителя, `pl` — итоговая статистика из `commitMatch()`.
- **`visit` в упражнениях** (`ex` не x01): `{ "seq": 4, "type": "visit", "leg": 1, "p": 0, "v": 100, "d": null }`:
  - `v` — очки подхода (`score`) или попадания в цель подхода (`round`, `sector`);
  - `d` — метки дротиков (`["T20", "20", "0"]`), необязательны, но должны давать `v`; у крикета обязательны (`v` не нужно), меньше 3 дротиков — только когда подход выигрывает лег.
- **`bull`** — ничья в леге без закрытия: `{ "seq": 41, "type": "bull", "leg": 2, "p": 0 }` — игрок `p` выиграл бросок в булл и лег. Принимается только при ничьей (`state.tie`).
- В `finish` у упражнений `pts` и `darts` — как считает `Games.state()`: `pts` — очки (у сектора попадания, у крикета метки).

Сервер проверяет:
- событие с уже принятым `seq` пропускается без ошибки, так что повторная отправка безопасна;
- `seq` больше ожидаемого → `409 seq_gap` с `expectSeq`: дослать с этого номера;
- подход сходится со счётом: верный игрок по очереди, `s` равен остатку, очки 0–180 и не из невозможных (163, 166, 169, 172, 173, 175, 176, 178, 179), закрытие допустимо → иначе `422 bad_event` с `seq`;
- в `finish` леги и сумма очков и дротиков совпадают с подходами;
- замок у другого устройства → `423 locked` с `by` (имя) и `until`.

Ответ:
```json
{ "ok": true, "seq": 3, "version": 15 }
```
Пачка принимается целиком или не принимается совсем. При `422` очередь останавливается: показать «Счёт не принят сервером», забрать события через `takeover` и восстановить счётчик по ним.
`seq` — последний принятый номер. Каждое принятое событие продлевает замок на 10 минут.

После `finish` результат попадает в сетку, а рейтинг и статистика пересчитываются.

### `POST /api/matches/:id/takeover` — `can.score` турнира или участник дружеского матча
Забрать ведение счёта на это устройство. Ответ `{ "match": Match, "events": [Event] }` — все события, чтобы восстановить счётчик. Следующий `seq` = последний + 1.

### `POST /api/matches/:id/reopen` — устройство с замком
Отменить завершение (кнопка «Отменить» сразу после конца матча). Матч снова `live`, результат снимается с сетки. Сервер сам добавляет событие `reopen`, поэтому следующий `seq` = `match.lastSeq` + 1.
- `409 result_locked` — следующие матчи сетки уже сыграны или идут.
- Вызывать только когда очередь неотправленного пуста.

Ответ `{ "match": Match }`.

### `DELETE /api/matches/:id`
- Идущий матч: бросить (устройство с замком или организатор). Игра сетки снова свободна.
- Сыгранный турнирный матч: снять результат (организатор). При `409 result_locked` — как в `reopen`.

Ответ `{ "ok": true }`.

### `GET /api/matches/:id?since=15`
Для зрителей и протокола.
- После версии 15 ничего не изменилось — `204`.
- Иначе:
  ```json
  { "match": Match, "events": [Event], "version": 18 }
  ```
  `events` — только события новее `since`; без `since` — все.

**`Match`:**
```json
{ "id": "gq7p0c2mzt", "status": "live", "tid": "t4", "r": 1, "i": 3, "mode": 501, "ltw": 3, "dbl": true, "starter": 0,
  "players": [{ "id": "p1", "name": "Артём Волков" }, { "id": "p8", "name": "Павел Зуев" }],
  "legs": [1, 0], "w": null, "state": { "leg": 2, "cur": 1, "scores": [321, 441], "avg": [88.4, 71.2], "last": { "p": 0, "pts": 180, "n": 3, "b": 0, "d": ["T20", "T20", "T20"] } },
  "lastSeq": 14, "version": 15, "started": 1760000000000, "finished": null,
  "lock": { "mine": false, "by": "Денис Карпов", "until": 1760000600000 }, "card": null }
```
- `status` — `live` или `done`.
- `legs` — выигранные леги (сервер считает по подходам).
- `state` — живой счёт:
  - `leg` — номер лега;
  - `cur` — кто бросает (`null`, когда матч выигран);
  - `scores` — остатки;
  - `last` — последний подход или `null`.
- `card` — `MatchCard` после `finish`.
- `ex` — упражнение или `null`; `q` — попытка квалификации `{ "id", "k" }` или `null`.
- `state.avg` — средний за подход (3 дротика) по всему матчу, `null` без бросков.
- У упражнений в `state`: `scores` — счёт лега (очки, попадания, очки крикета; у x01 — остатки), `vis` — подходов в леге у каждого, `marks` — метки крикета `[{ "20": 3, … }]`, `tie` — кто разыгрывает булл (тогда `cur: null`); у `last` бывает `{ "p": 0, "tb": 1 }`.
- **`Event`** — то же, что в `/events`, плюс поле `t` (время приёма). Бывает ещё тип `reopen` (см. выше).

Счёт у зрителя можно брать из `state` или считать по подходам: остаток = `mode` − сумма `pts` игрока в текущем леге. Первым в леге `k` бросает игрок `(starter + k − 1) mod число игроков`.

## Табло (живой счёт без задержки)

Для телевизора у организатора и для страницы турнира. Сервер сам присылает изменения через Server-Sent Events, через 50–100 мс после записи подхода. Опрашивать ничего не нужно.

### `GET /api/tournaments/:id/live`
Снимок без потока:
```json
{ "version": 57, "matches": [LiveMatch] }
```
`version` — версия турнира, `matches` — идущие матчи.

**`LiveMatch`**:
```json
{ "id": "gq7p0c2mzt", "r": 1, "i": 3, "status": "live", "mode": 501, "ltw": 3,
  "players": [{ "id": "p1", "name": "Артём Волков" }, { "id": "p8", "name": "Павел Зуев" }],
  "legs": [1, 0], "w": null, "state": { "leg": 2, "cur": 1, "scores": [321, 441], "avg": [88.4, 71.2], "last": { "p": 0, "pts": 180, "n": 3, "b": 0, "d": null } },
  "version": 15, "lastSeq": 14, "by": "Денис Карпов" }
```
`by` — кто ведёт счёт. `ex` и `q` — как у `Match`: попытки квалификации тоже идут в поток (у них `r` и `i` равны `null`).

### `GET /api/tournaments/:id/stream` — поток `text/event-stream`
События:

| `event` | `data` | Что делать |
|---|---|---|
| `snapshot` | как у `/live` | приходит сразу при подключении и после сбоя связи сервера с базой; заменить всё |
| `match` | `LiveMatch` | матч начался, новый подход, отмена, завершение (`status: "done"`); заменить матч по `id`, если `version` новее |
| `match` | `{ "id": "…", "deleted": true }` | матч брошен или результат снят: убрать с табло |
| `tour` | `{ "version": 58 }` | изменилась сетка: один раз запросить `GET /api/tournaments/:id` |
| `tour` | `{ "deleted": true }` | турнир удалён |

Пример:
```js
const es = new EventSource('/api/tournaments/' + id + '/stream');
es.addEventListener('snapshot', e => showAll(JSON.parse(e.data)));
es.addEventListener('match', e => showMatch(JSON.parse(e.data)));   // анимация 180, перебора и закрытия — по state.last
es.addEventListener('tour', () => reloadBracket());
```
- `EventSource` сам переподключается при обрыве: через 3 с, сервер задаёт это в `retry`. После переподключения снова приходит `snapshot`.
- Если табло открыто, сетку можно обновлять по событию `tour` вместо опроса раз в 30 с.
- На телефонах, где поток не держится (свёрнутая вкладка), достаточно опроса `GET /api/tournaments/:id?since=` раз в 30 с.

## Права

| Действие | Кто может |
|---|---|
| Смотреть всё | все, без входа |
| Создать турнир, гостя, дружеский матч | вошедший |
| Изменить и удалить турнир, запустить, записать другого | организатор, админ |
| Записаться и отписаться самому | вошедший, пока идёт регистрация |
| Вести счёт турнирного матча | организатор турнира или игрок этой пары, админ |
| Снять результат | организатор, админ |

Без входа дружеские игры работают как сейчас: остаются на телефоне и на сервер не отправляются.
