# ТЗ: сервер и база (Oche)

**Исполнитель:** Даниил (с ИИ).
**Цель:** сервер, через который все телефоны видят одни и те же турниры, сетки и счёт.
**Объём:** 8–10 рабочих дней. VPS покупается только на последнем шаге.

Страницу делает второй разработчик (`docs/tz-frontend.md`). Связь между нами идёт через договор API (`docs/api.md`).

---

## Стек

- Node.js 22 + Fastify.
- PostgreSQL 16, локально через Docker (`docker compose up`).
- Миграции в виде SQL-файлов: `db/migrations/001_init.sql`, `002_….sql`.
- Логика сетки — общий модуль `shared/bracket.js`. Его делает второй разработчик, сервер только подключает.
- Сессии хранятся в базе, браузер получает httpOnly-cookie.

**Структура папок**
```
server/      код сервера (routes/, services/, index.js)
db/          migrations/, seed.js
shared/      bracket.js (от второго разработчика)
docs/        api.md, server-load.md
.env.example пример настроек
```

## Задачи

### A0. Договор API — 0,5 дня, первым делом
Файл `docs/api.md`. Для каждого запроса указать:
- метод и адрес;
- кто имеет право его вызывать;
- тело запроса и ответ (с примерами JSON);
- коды ошибок.

Обязательные разделы: вход, игроки, турниры, матчи и подходы, рейтинг и лента, формат ошибок `{ error: { code, message } }`.

**Готово, когда** второй разработчик прочитал договор, согласовал его и может по нему сделать заглушку.

### A1. База данных — 1 день

| Таблица | Поля (главные) |
|---|---|
| `players` | id, name, city, club, vk_id (уникальный, может быть пустым для гостей), rating, created_at |
| `player_stats` | player_id, matches, wins, avg3, checkout_pct, n180, n140, n100, high_co, updated_at |
| `tournaments` | id, name, city, venue, format (pl/ko/rr), mode (301/501/701), legs_to_win, seed (r/x), status (reg/live/done), owner_id, version, created_at |
| `entries` | tournament_id, player_id, seed_no |
| `matches` | id, tournament_id, slot (номер в сетке), a_id, b_id, legs_a, legs_b, winner_id, status, marker_device, marker_until, version |
| `visits` | match_id, seq, leg, player_idx, points, darts, bust, checkout, undo_of, created_at |
| `sessions` | id, player_id, device_id, expires_at |

Индексы:
- `visits (match_id, seq)` — уникальный;
- `matches (tournament_id)`;
- `tournaments (status)`;
- `players (vk_id)`.

`db/seed.js` создаёт 30 игроков и 3 турнира: один в регистрации, один идёт, один завершён.

**Готово, когда** миграции поднимают пустую базу с нуля одной командой, а сид наполняет её демо-данными.

### A2. Каркас сервера — 0,5 дня
- Настройки из `.env`: порт, адрес базы, ключи VK.
- Пул соединений к PostgreSQL на 10–20 соединений.
- Лог запросов и ошибок.
- Единый формат ошибок.
- Ограничение частоты: 5 запросов в секунду с одного устройства.
- `GET /api/health` отвечает `{ ok: true }`.

**Готово, когда** `npm run dev` запускает сервер, `/api/health` отвечает, а при выключенной базе сервер пишет понятную ошибку.

### A3. API турниров — 1–2 дня
- Создать турнир.
- Изменить турнир, пока идёт регистрация.
- Удалить турнир (только организатор).
- Записать и снять участника.
- Запустить турнир: посев и сетка строятся на сервере через `shared/bracket.js`, в базе создаются все матчи.
- Список турниров с фильтром по статусу.
- Страница турнира. С параметром `?since=version`: если ничего не изменилось — `204`, иначе только изменённые матчи и новая версия.
- Любое изменение турнира увеличивает `tournaments.version`.

**Готово, когда** турнир на 16 игроков создаётся и запускается, а сетка совпадает с той, что строит страница.

### A4. API матча — 1–2 дня, самое важное
- **Замок.** `POST /matches/:id/lock` закрепляет устройство за матчем. Если матч уже ведёт другой телефон, вернуть `423` с именем. Отдельный запрос «забрать ведение счёта». Каждый подход продлевает замок.
- **Подход.** `POST /matches/:id/visits` с телом `{ seq, leg, playerIdx, points, darts, bust, checkout }`.
  - Повтор уже записанного `seq` — ответить `ok`, ничего не меняя.
  - Пропуск `seq` — `409 { expectSeq }`.
  - Правдоподобие: очки 0–180, кроме невозможных 163, 166, 169, 172, 173, 175, 176, 178, 179; закрытие только допустимыми очками.
  - Запись подхода и `version + 1` — в одной транзакции.
- **Отмена** — отдельное событие `undo`. Историю не удаляем.
- **Конец матча.** Записать результат в сетку, увеличить версию турнира, пересчитать статистику (A5).
- **Для зрителей:** `GET /matches/:id?since=version` возвращает `204` или только новые подходы.
- Версии активных матчей держать в памяти, чтобы `204` отдавался без запроса к базе.

**Готово, когда:**
- двойная отправка не даёт дубля;
- пропуск даёт `409`;
- второй телефон получает `423`;
- после конца матча в сетке открывается следующая пара.

### A5. Рейтинг и статистика — 1 день
- После завершения матча пересчитать `player_stats` обоих игроков и рейтинг (формула та же, что на странице).
- Отдать готовые цифры без пересчёта: таблица рейтинга, профиль, история матчей игрока, лента последних результатов.

**Готово, когда** профиль открывается одним простым запросом, а цифры совпадают с теми, что показывала демо-версия.

### A6. Вход через VK и права — 1–2 дня
Серверная половина входа. Кнопку и экраны делает второй разработчик.
- `GET /api/auth/vk/callback` принимает код от VK и обменивает его на данные пользователя. Для обмена нужен **секретный ключ приложения, который нельзя держать в браузере**, поэтому эта часть только на сервере.
- Найти или создать игрока по `vk_id`, создать сессию, поставить cookie.
- `GET /api/me` — кто вошёл; `POST /api/logout` — выход.
- Права:
  - смотреть могут все, без входа;
  - создать турнир может любой вошедший;
  - менять и удалять турнир — только организатор;
  - вести счёт — организатор турнира или игрок этого матча;
  - админу можно всё.

**Готово, когда** вход работает на `localhost`, а запрос без прав получает `403`.

### A7. Исправления — 0,5 дня
По отчёту нагрузочного теста и тестов с телефонов от второго разработчика.

### A8. Перенос на VPS — 1 день, в самом конце
- Ubuntu 24.04: nginx, Node 22, PostgreSQL 16, pm2 (2 процесса).
- nginx раздаёт статику с gzip и кэшем, на Node пускает только `/api`.
- HTTPS через Let's Encrypt, с автопродлением.
- Ежедневный `pg_dump` по cron, хранить 14 дней. Один раз проверить восстановление из копии.
- Оповещение в Telegram, если сервер не отвечает или кончается место на диске.
- Скрипт `deploy.sh`: обновление кода и миграций одной командой.

**Готово, когда** сайт открывается по домену через HTTPS, вход через VK работает, а резервная копия создаётся каждую ночь.

## Что получаю от второго разработчика
- `shared/bracket.js` с тестами — **к концу первой недели**, нужен для A3.
- Отчёт нагрузочного теста и список ошибок с телефонов — на третьей неделе.

## Что отдаю второму разработчику
- `docs/api.md` — в первый день.
- Локальный сервер с сидом, который он может запустить у себя, — к концу второй недели.

## Подготовить без VPS
- Зарегистрировать приложение в VK ID. Для разработки адрес возврата `http://localhost`.
- Купить домен.
- Написать политику обработки персональных данных (имя, город, клуб, VK ID).

## Правила
- Изменения API сначала вносятся в `docs/api.md` и согласуются, потом в код.
- Логику сетки на сервере не переписывать: только `shared/bracket.js`.
- Секреты хранятся только в `.env`, в репозиторий их не коммитить.
