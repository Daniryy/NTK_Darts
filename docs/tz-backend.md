## 1. Договор API
`docs/api.md`: все запросы, что отправляем, что приходит, коды ошибок. Согласую со вторым разработчиком до начала работы.

## 2. База данных
Таблицы:
- `players` — игроки (имя, город, клуб, VK ID, рейтинг);
- `player_stats` — готовая статистика игрока;
- `tournaments` — турниры (название, формат, очки, до скольких побед, статус, организатор, версия);
- `entries` — участники турнира и посев;
- `matches` — матчи сетки (кто играет, счёт, победитель, кто ведёт счёт, версия);
- `visits` — подходы (номер `seq`, очки, дротики, закрытие);
- `sessions` — входы.

Миграции, индексы, демо-данные.

## 3. Сервер
- **Турниры:** создать, изменить, удалить, записать и снять участника, запустить (сервер сам строит сетку), список, страница турнира.
- **Матчи:**
  - один телефон ведёт счёт, остальные смотрят;
  - приём подходов по `seq`: дубль игнорируется, при пропуске ответ `409`;
  - проверка очков на правдоподобие;
  - отмена подхода;
  - конец матча записывается в сетку.
- **Обновления:** запрос с `?since=версия` получает `204`, если ничего не изменилось, или только новое.
- **Рейтинг и статистика:** пересчёт после матча, профиль, таблица рейтинга, лента.
- Ограничение частоты запросов, лог ошибок.

## 4. Вход через VK и права
- Обмен кода VK на пользователя (секретный ключ только на сервере), сессия в cookie, `/api/me`, выход.
- Права:
  - смотреть могут все;
  - турнир меняет и удаляет организатор;
  - счёт ведёт организатор или игрок матча.

## 5. Запуск на VPS
nginx, Node, PostgreSQL, HTTPS, ежедневные резервные копии, оповещения при падении, обновление одной командой.
