# ТЗ: страница, логика сетки, тесты (Oche)

**Исполнитель:** второй разработчик. **Базу данных не трогает.**
**Цель:** готовая страница (`index.html`) берёт данные с сервера вместо localStorage, счёт надёжно доходит даже при плохой связи, всё проверено тестами.
**Объём:** 8–10 рабочих дней.

Сервер и базу делает Даниил (`docs/tz-backend.md`). Работаем в одном репозитории: каждое изменение коммитим с понятным описанием. По договору API `docs/api.md`; пока нужной части сервера нет, страница работает в демо-режиме.

**Что уже есть и не переделывается:** все экраны, сетка трёх форматов, счётчик, статистика, темы. Задача — подключить их к серверу.

---

## Задачи

### B1. Модуль сетки — 1 день, нужен Даниилу к концу первой недели
- Перенести из `index.html` в `shared/bracket.js` всё, что считает сетку: `seedOrder`, `setBracket`, `feeders`, `resolver`, `routeFor`, `gameState`, `gameNums`, `placeRange`, `placeOf`, `tProgress`, `rrGames`, `standings` и то, от чего они зависят.
- Модуль без DOM и localStorage, на чистых функциях.
- Должен работать и в браузере, и в Node (`<script>` и `require`/`import`).
- Тесты (`node --test`):
  - 3–64 игроков во всех форматах (pl, ko, rr);
  - каждый игрок получает ровно одно место;
  - пустые места (BYE) проходят автоматически;
  - случайные результаты 1000 раз подряд не ломают сетку;
  - номера матчей совпадают с тем, что показывает страница.
- `index.html` подключает этот модуль, внешний вид сетки не меняется.

**Готово, когда** тесты зелёные, а страница выглядит и работает как раньше.

### B2. Слой данных — 1 день
- Файл `api.js`: все обращения к серверу в одном месте (`api.tournaments.list()`, `api.match.sendVisit()` и т. д.).
- Переключатель «демо (localStorage) / сервер», чтобы демо-версия работала без сервера.
- Единая обработка ошибок:
  - нет сети — понятное сообщение;
  - `401` — предложить войти;
  - `403` — «нет прав»;
  - `5xx` — «сервер недоступен, повторить».

### B3. Экраны с сервера — 2–3 дня
- Лента, список турниров, страница турнира (сетка, места, таблица), рейтинг, профиль, создание турнира и регистрация.
- Сетку, места и подписи считает страница через `shared/bracket.js`. С сервера приходят только участники и результаты матчей.
- На каждом экране три состояния: «загружается» (скелетон), «ошибка» (кнопка «Повторить»), «пусто».
- Обновление свайпом вниз на ленте, рейтинге и профиле.

### B4. Очередь неотправленного в счётчике — 1–2 дня
- Каждый подход сначала сохраняется в `localStorage['oche.outbox']`, затем отображается на экране, затем отправляется.
- Отправка строго по порядку `seq`, по одному: следующий подход — только после `ok` предыдущего.
- На ошибку — повтор через 1, 2, 5, 10, 30 с. При событиях `online` и `visibilitychange` — досылка сразу.
- На `409 { expectSeq }` дослать недостающие подходы из очереди.
- В шапке счётчика индикатор «не отправлено: N». Игра при этом не блокируется.
- При открытии матча запросить замок. Если сервер ответил `423` (матч ведёт другой телефон), включить режим просмотра с кнопкой «Забрать ведение счёта» и подтверждением.
- Отмена подхода — тоже событие в очереди.

Подробности в `docs/server-load.md`, раздел 2.

**Готово, когда** при выключенной на 2 минуты сети подходы вводятся, а после включения все доходят по порядку и без дублей.

### B5. Автообновление — 0,5–1 день
Модуль `poller.js`:
- живой матч у зрителя — раз в 10 с; если ответы `204` подряд, интервал растёт до 15, 20, 30 с; при изменении снова 10 с;
- страница турнира — раз в 20–30 с;
- лента, рейтинг и профиль — без автообновления;
- свёрнутая вкладка ничего не запрашивает, а при возврате сразу делает один запрос;
- законченный матч опрашивать перестаём;
- к интервалу добавлять случайные ±20%;
- запрос с `?since=version`, на `204` ничего не перерисовывать.

Пример в `docs/server-load.md`, раздел 3.

### B6. Вход через VK — 1 день
Половина входа на странице. Обмен кода и сессии делает сервер (Даниил).
- Кнопка «Войти через VK», которая ведёт на адрес из `docs/api.md`. После возврата запросить `GET /api/me`.
- Без входа можно всё смотреть. При попытке создать турнир или вести счёт предложить войти.
- Кнопки «Играть», «Счёт», «Изменить» и «Удалить турнир» показывать только тем, кому разрешено по ответу сервера.
- Кнопка «Выйти» в настройках.

### B7. Тесты с телефонов — 0,5 дня
Минимум 3 телефона, локальный сервер в одной Wi-Fi-сети.
1. Обрыв сети у маркера на 2 минуты, во время которого вводится 5 подходов. После включения у зрителей все 5, по порядку.
2. Два телефона открывают один матч: второй получает режим просмотра.
3. Полный турнир на 16 игроков в формате «с розыгрышем мест»: все места определены, сетка у всех одинаковая.
4. Свёрнутая вкладка 5 минут: по логам сервера она не делает запросов.

**Результат:** список найденных ошибок с шагами воспроизведения.

### B8. Нагрузочный тест — 0,5 дня
- k6 или autocannon, работает только через API, база не нужна.
- Сценарий: N маркеров отправляют подход раз в 30 с, 10% зрителей опрашивают матч раз в 10 с, страница турнира опрашивается раз в 25 с.
- Прогнать для 250, 500, 1000 и 2000 игроков.
- В отчёт: p50 и p95 времени ответа, доля ошибок, загрузка CPU и памяти. Цель — p95 меньше 200 мс, CPU меньше 50%.

### B9. Доводка — 1 день
- Понятные тексты ошибок сети.
- PWA: `manifest.json`, иконки, установка на экран телефона.
- Заставка «нет сети», если страница открыта офлайн.
- Счётчик не засыпает во время матча (wake lock уже есть, проверить).

## Что получаю от Даниила
- `docs/api.md` — в первый день.
- Готовые части сервера — по мере появления в репозитории.

## Что отдаю Даниилу
- `shared/bracket.js` с тестами — **к концу первой недели**.
- Отчёт нагрузочного теста и список ошибок с телефонов — на третьей неделе.

## Порядок
```
Неделя 1: согласовать api.md → B1 модуль сетки → B2
Неделя 2: B3, B4, B5, B6 (подключаем части сервера по мере готовности)
Неделя 3: B7 тесты с телефонов, B8 нагрузка, B9 доводка
```

## Правила
- Если в API чего-то не хватает, сначала правка в `docs/api.md` и согласование, потом код.
- Логика сетки меняется только в `shared/bracket.js`, с прогоном тестов.
- Демо-режим (без сервера) должен продолжать работать.
